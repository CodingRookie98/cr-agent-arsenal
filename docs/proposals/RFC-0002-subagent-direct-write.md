## 1. 背景与业务痛点 (Why)

### 1.1 现象：写盘者与内容作者分离，指纹退化为自证闭环

RFC-0001 解决了「报告全文从未落盘」，但其选定方案把写盘动作判给了**主智能体**（[RFC-0001 §3.7](../../docs/proposals/RFC-0001-review-report-archive.md)）：

> **默认**：主智能体在收到子智能体真实返回后**逐字写盘**，并计算 SHA256 登记至锚点与索引；
> R1/R2 子智能体的 **Read-Only 约束保持不变**（不修改工作树、分支与索引）。

该方案同时自认了它的信任边界：

> 指纹由转录者本人计算登记，属自证式校验，**检不出**转录期的改写、压缩与选择性摘录。

即：**报告的作者是子智能体，写盘者和指纹计算者都是主智能体**。SHA256 能证明「落盘之后文件未被改动」，不能证明「落盘内容等于子智能体的原始返回」。当主智能体压缩、改写或选择性摘录了报告，门禁无法察觉——因为校验值是它自己算的。

### 1.2 后果：三类受众各自承担未被覆盖的风险

| 受众 | 受损方式 |
| :--- | :--- |
| **R2 元架构师子智能体** | 通道 A 读到的归档文件是**转录产物**；指纹核验只能证明「文件未变」，不能证明「文件忠实于 R1」 |
| **人类参与者** | `git clone` 后读到的「逐字原文」属性不可证，只能选择信任转录者的纪律 |
| **编排者（`goal-loop`）** | 无法区分某轮报告是子智能体原文还是主智能体转录产物——两者在台账里长得完全一样 |

### 1.3 根因：内容作者没有写盘权，写盘者无法自证忠实

把「写盘」与「核验」交给同一个主体，是自证式校验的结构性来源。RFC-0001 已在 [ADR-0001 §3.2](../../docs/explanation/decisions/0001-review-evidence-archive-layer.md) 显式登记该残差，并把它转嫁给「D4 的 R2 文件通道」——但 R2 读到的文件本身就是转录产物，该转嫁并未真正闭合缺口。

### 1.4 旁证：替代路径已被预留并估算了成本

[RFC-0001 §7.3 A1](../../docs/proposals/RFC-0001-review-report-archive.md) 把「主智能体转录」登记为默认假设（影响面 LOW、可否决），并写明替代路径：

> 若实测转录失真频繁，改为授权子智能体写报告文件（**需为 Read-Only 约束开例外并做路径预授权**），估算 +0.5 天

本提案即执行该替代路径，把默认假设 A1 升级为已决项。

## 2. 目标与非目标 (Goals & Non-Goals)

### 2.1 核心目标 (Goals)

* **G1 消除转录环节**：报告原文由**作者本人**直接落盘，主智能体不再经手内容。
* **G2 写作者与核验者分离**：主智能体从「转录者」转为「校验者」，独立复算指纹并与子智能体回报值比对。
* **G3 保持宿主无关**：无写盘能力的宿主保留转录降级通道，且**降级必须显式可审计**（不得静默降级）。
* **G4 路径收敛**：子智能体被授权写**且仅写**唯一目标路径；路径由主智能体在派发前机械确定。
* **G5 不破坏既有交付面**：归档根、命名规范、报告 schema、逐字红线与既有 7 项门禁校验语义全部不变。

### 2.2 明确非目标 (Non-Goals / 防蔓延红线)

* **N1 不做宿主沙箱级路径强制**：`dual-round-review` 是 `npx skills add` 分发的宿主无关资产，技能层**没有**（也不应假装拥有）限制子智能体文件系统写入面的能力。路径预授权是**提示词契约**，其强制力等于宿主的实际能力——该事实必须在技能文档中诚实登记，不得表述为「已隔离」。
* **N2 不改归档根与命名规范**：`<归档根>/<YYYY-MM-DD>-<slug>/<轮次>-<base7>..<head7>.md` 全部沿用。
* **N3 不给报告文件添加任何元数据**：守住 G1 逐字红线，禁止控制头、禁止来源标注、禁止尾部附注。
* **N4 不改变审查内容与输出格式**：R1 五区块、R2 三区块、稳定 ID 体系、Diff 范围边界锁全部不变。
* **N5 不改变既有门禁语义**：`check-review-report.sh` 的 7 项校验判定规则不动，仅**追加**校验项。

## 3. 核心设计与契约草案 (How - Technical Draft)

### 3.1 双通道写入拓扑

| 通道 | 触发条件 | 内容作者 | 写入者 | 台账登记 | 指纹责任 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **直写** (`direct`) | 默认；子智能体具备写盘能力且目标路径可写 | 子智能体 | **子智能体** | `direct` | 子智能体回报 + **主智能体独立复算比对** |
| **转录降级** (`transcribed`) | 子智能体无写能力、写入失败或路径不可用 | 子智能体 | 主智能体 | `transcribed` | 主智能体计算（**自证残差保留**，登记降级原因） |

两通道产出的报告文件**格式完全一致**，门禁对二者一视同仁；差异只体现在台账的「写入形态」列与锚点的降级记录中。这是刻意的：报告是审计凭据，其产生方式属于**过程元数据**，不得污染报告本体（守 N3）。

### 3.2 路径预授权契约

**路径确定（派发前，主智能体执行）**：

```
<归档根>/<YYYY-MM-DD>-<slug>/<轮次标记>-<base7>..<head7>.md
```

* **归档根**与**归档目录**：由 `prepare-review-context.sh --slug=<slug>` scaffold 产出并登记至锚点「归档索引」段（既有能力，不新增）。
* **轮次标记**：`r1` / `r2` / `delta-r1` / `delta-r2`。
* **base7 / head7**：基线提交短 SHA 前 7 位。

**预授权六条**（第 ② 条为 Delta 阶段 R1-1 回归补充的确定性不变式）：

1. **主智能体确定路径**：路径在派发提示词中以字面值内联，子智能体**不得自选、不得推断、不得改写**路径。
2. **路径必须是基线的确定函数**：`--round` 与自适应模式（自动判定 working/range）**互斥**——必须显式给出 `BASE_SHA [HEAD_SHA]`，或显式使用 `--working` / `--staged`。若允许自适应，同一命令会因工作区被 scaffold 自身弄脏而在两次调用间输出不同文件名（净树走 range、脏树走 working），使 Write-Once 保护静默失效并产生门禁不可枚举的孤儿报告（**R1-1 回归**：无基线调用现由脚本显式拒绝，rc≠0）。
3. **目录由主智能体预创建**：归档目录必须已存在（scaffold 已保证）；子智能体**不得创建目录**。
4. **文件不预创建**：目标文件必须**不存在**，由子智能体一次性创建。
5. **Write-Once**：子智能体写入前须检查目标文件不存在；**已存在则中止并如实报告**，严禁覆盖（保护 Delta 再循环既有报告）。
6. **单一例外**：该路径是子智能体**唯一**被授权的写入面；归档索引 `README.md`、锚点文件、`.gitignore`、任何源码与配置一律禁止写入。

### 3.3 指纹双重核验契约

| 步骤 | 执行者 | 动作 |
| :--- | :--- | :--- |
| ① | 子智能体 | 写盘后计算文件 SHA256，在返回中**显式回报**：目标路径 + 文件字节数 + SHA256 全值 |
| ② | 主智能体 | 独立执行 `sha256sum <path>` 取得**全值**，与子智能体回报的**全值**逐字比对（**R1-4 回归**：两侧同为 64 位；仅登记台账时取前 12 位——原表述「取前 12 位与回报值比对」在回报为全值时恒不相等，会误判写入异常） |
| ③ | 主智能体 | **一致** → 登记台账与锚点；**不一致或文件缺失** → 判定为写入异常，按 §3.8 收口 |

**与 RFC-0001 的差异**：指纹不再由转录者计算。直写通道下，「写盘者」与「指纹回报者」是同一个（子智能体），但「指纹登记者」是主智能体且**必须独立复算**——复算动作使主智能体无法在不被发现的情况下替换文件内容（替换后需同步伪造回报值，而该伪造行为本身即越出 §3.7 的写入例外）。

**诚实登记（R1-6 回归 · 措辞已按 Delta 审查修正）**：本契约的真实改进边界是**「写盘后替换文件内容」可被机械检出**——替换后文件指纹与子智能体回报值不再匹配。但它**不消除**自证：成功路径的模板只要求「写盘 + 回报三行」，**回传全文仅出现在失败分支**，因此「文件内容是否忠实于作者的审查推理」在契约层**没有比对物**，**作者侧仍是单人自证**；主智能体亦仍掌握台账登记权。

> **原表述勘误**：本节早期版本写作「只把它从『单人自证』变为『需要两人串通』」——该表述对**作者侧**不成立（成功路径不回传原文，三项核验输入全由写作者产出），属过度承诺，现已撤回。**不采纳**「成功路径回传全文」的补实现方案：那会把刚刚消除的转录通道请回，且同源内容不构成独立核验。

### 3.4 轮次台账 schema 扩展

```markdown
| 轮次 | 基线 | 派发句柄 | 报告文件 | SHA256(前 12 位) | 结论 | 写入形态 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| r1 | 771ad29..a1b2c3d | `d2da7baf` | r1-771ad29..a1b2c3d.md | aeb36bf82bb5 | 🔴 阻断交付 | direct |
```

* **追加第 7 列「写入形态」**，取值 **必须**为 `direct` 或 `transcribed` 之一。
* 既有 6 列**列序与语义完全不变**（`check-review-report.sh` 固定解析 `$5`=报告文件、`$6`=SHA256，追加末尾列不影响既有解析）。
* 该列是**唯一**能区分「原文」与「转录产物」的可审计属性——没有它，G3 的「降级必须显式」无法落地。

### 3.5 机械门禁校验项

在 `check-review-report.sh` 既有 7 项之上**追加**第 8 项：

> **8) 写入形态合法性**：轮次台账每一行的「写入形态」列必须存在，且取值必须精确等于 `direct` 或 `transcribed`；缺失或取值非法即判失败。

**不新增**「报告确实是子智能体写的吗」这类校验——该属性**不可机械验证**（同 SHA256 的自证边界），强行声称可校验即制造虚假安全感。

### 3.6 关键接口改造

| 接口 | 现状（V2.1.0） | 改造后（V2.2.0） |
| :--- | :--- | :--- |
| R1 派发提示词 | Read-Only 全禁；报告经返回文本回传 | **写入例外**：仅授权目标路径；要求写盘并回报指纹 |
| R2 派发提示词 | 同上；报告经返回文本回传 | 同上 |
| R1/R2 落盘动作 | 主智能体逐字写盘 | **子智能体直写**；主智能体独立复算指纹并登记 |
| 轮次台账 | 6 列 | **7 列**（追加「写入形态」） |
| `prepare-review-context.sh` | `--slug` scaffold 归档目录与索引 | 新增 `--round=<r1\|r2\|delta-r1\|delta-r2>`：额外打印**本轮报告目标路径**，供派发前机械化取值 |
| `check-review-report.sh` | 7 项校验 | **8 项**（追加写入形态合法性） |
| 异常降级 | 落盘失败 → 收口 | **新增转录降级**：子智能体不可写 → 主智能体转录 + 台账登记 `transcribed` |

### 3.7 写入约束例外条款（安全约束 · 本提案的核心契约变更）

两轮模板现行的 `Read-Only constraint` 行**替换**为：

```
Write-scope constraint: You must not modify the working tree, branch, or index,
with exactly ONE pre-authorized exception: you MAY create and write the single
report file at <REPORT_PATH> (and nothing else). Creating directories, editing
the archive index README.md or the runtime anchor, staging files, or touching any
other path is forbidden. If <REPORT_PATH> does not exist and is writable, write
your report there as your final action, then report the path, byte size and
SHA256. If it already exists, or you cannot write it, do NOT attempt a workaround:
report the limitation and return the report text in your reply instead.
```

**约束面变化（必须显式承认）**：子智能体的授权写入面从「零」扩大为「唯一一个文件」。在具备路径级隔离能力的宿主上这是可强制的收窄授权；在**不具备**该能力的宿主（如子智能体继承工作区写权限的实现）上，实际能力不变，约束强度等同于提示词自律。**技能文档必须按宿主能力分级描述，不得统一表述为「已隔离」。**

### 3.8 异常分支与降级策略

| 异常 | 处置 |
| :--- | :--- |
| 子智能体无写盘能力 | 主智能体转录原文，台账登记 `transcribed`，锚点记录降级原因；**报告文件格式不变** |
| 子智能体写入失败（权限/磁盘/路径） | 同上；子智能体须在返回中如实报告失败事实，**严禁**重试到其他路径 |
| 目标文件已存在 | 视为**基线漂移缺陷**：子智能体中止并报警，**不得覆盖**既有报告；主智能体排查命名冲突后再派发 |
| 归档目录不存在 | 子智能体**不得**自行创建；回报失败 → 走转录降级；主智能体补 scaffold |
| 指纹复算不一致 | 判定为**写入异常**（篡改/截断/并发写），不得登记台账；按 `goal-loop` `host-adapters.md` §5 收口并记录 |
| 子智能体返回了报告文本但未写盘 | 主智能体**不得**默认转录放行：须先确认是否为能力缺失；确认后方可降级并登记 `transcribed` |
| 报告体积过大 | 直写不截断；提示词侧维持既有 800 行 Diff 内联阈值与按需调阅授权 |

## 4. 备选方案权衡与争议焦点 (Alternatives & Trade-offs)

### 方案 A（本提案选定）：子智能体直写 + 路径预授权 + 双通道登记

* **核心理念**：让内容作者写自己的内容，把主智能体从转录者升格为核验者。
* **优势**：消除转录环节（G1）；写盘与核验分离（G2）；降级可审计（G3）；改动集中在提示词契约与台账 schema，脚本改动面小。
* **已知代价**：子智能体写入授权面从零扩大到单文件（§3.7）；在无路径强制的宿主上该扩大仅是提示词约束；`direct` 形态的声明本身仍是自证的（§3.3 诚实登记）。

### 方案 B（未采纳）：维持现状，仅强化转录纪律

* **核心理念**：不改契约，靠主智能体自律 + 事后指纹。
* **未采纳理由**：这正是 RFC-0001 §3.7 已经存在的状态，其残差已被 ADR-0001 §3.2 实证登记；「强化纪律」不是可验证的机制改进，属于把结构问题降级为态度问题。

### 方案 C（未采纳）：新增第三方归档工具链（签名/时间戳）作为独立进程写入

* **核心理念**：引入外部签名或可信时间戳，用密码学替代人工转录。
* **未采纳理由**：需求方是宿主无关的分发技能，引入外部依赖与密钥管理会把「审查归档」变成需要运维的基础设施；且签名解决的是「谁写的」，不解决「内容是否等于作者返回」——后者靠直写即可消除。投入产出比不成立。

### 争议焦点与裁决

| 焦点 | 分歧 | 裁决 |
| :--- | :--- | :--- |
| 焦点 1：预授权能否算「隔离」？ | 「授权一个路径」是否等同于路径隔离 | **不能**。技能层无强制能力，文档必须按宿主能力分级描述（§3.7）；不诚实表述即为虚假安全 |
| 焦点 2：是否保留转录通道？ | 彻底切换 vs 保留降级 | **保留**。技能必须宿主无关（G3）；降级通过台账列显式化，静默降级才是要禁止的行为 |
| 焦点 3：`direct` 声明是否也是自证？ | 新增列能否真正提升可信度 | **是自证，但仍有价值**：它把「静默降级」变成「显式声明」，是打破沉默的机制；不得宣称其机械可验证 |
| 焦点 4：指纹复算是否多余？ | 子智能体已回报指纹 | **不多余**。复算使主智能体无法在不被发现的情况下替换文件（§3.3），是 G2 的落地动作 |

## 5. 术语表与易歧义对齐 (Glossary & Terminology Alignment)

### 5.1 核心术语定义 (Core Term Definitions)

| 术语 | 定义 | 判定边界 |
| :--- | :--- | :--- |
| **直写通道 (Direct-Write Channel)** | 子智能体将报告原文直接写盘至预授权路径，主智能体不经手内容 | 以报告文件是否由子智能体创建为判据 |
| **路径预授权 (Path Pre-authorization)** | 派发时把唯一可写目标路径以字面值写入提示词，并为 Write-Scope 约束开该路径的例外 | 路径必须由主智能体确定，子智能体自选路径即失效 |
| **转录降级 (Transcription Fallback)** | 子智能体无法写盘时，退回主智能体逐字转录 | 必须登记台账 `transcribed`，静默转录即违规 |
| **写入形态 (Write Mode)** | 台账登记该轮报告的产生方式 | 取值仅 `direct` / `transcribed`，第三值即非法 |
| **指纹复算 (Independent Re-hash)** | 主智能体独立计算文件 SHA256 并与子智能体回报值比对 | 未复算即登记属违规；不一致须收口 |
| **写作用户面 (Write Scope)** | 子智能体被允许修改的路径集合 | V2.2.0 起为「零 + 唯一报告路径」 |

### 5.2 易歧义与同义词裁决 (Ambiguity & Synonym Resolution)

| 易歧义表述 | 裁决 |
| :--- | :--- |
| 「只读子智能体」 | V2.2.0 起**不准确**：子智能体持有单文件写入例外。正式表述为「**Write-Scope 受限子智能体**」 |
| 「逐字归档」 | 指**内容不发生转录变形**；直写通道下由写作者保证，转录通道下由转录者保证（残差登记在台账） |
| 「隔离」 | 仅当宿主具备路径级强制时才可使用；无该能力时须写「提示词约束」 |
| 「子智能体直接写报告」的口语表述 | 正式术语为「直写通道 (Direct-Write Channel)」 |

### 5.3 禁用称谓与历史别名 (Deprecated Aliases)

* **禁用**：「Read-Only 约束不变」（V2.2.0 起不再成立，该短语仅可用于描述 V2.1.0 及更早版本）。
* **禁用**：「指纹可检出转录失真」（V2.1.0 已自认不可，V2.2.0 后直写通道消除该场景，转录通道下残差仍在）。
