## 1. 背景与痛点

调研报告给出三条硬证据，指向同一个缺口——**我们测得到「文档写得规不规范」，测不到「文档还对不对」**：

| 证据 | 数值 | 对我们的含义 |
| :--- | :--- | :--- |
| TRACE（arXiv:2604.03447） | 实现变更而文档未动时，模型检出率下降 21–43 个百分点 | 最需要检测的腐化形态恰是检测盲区 |
| 六周实证（arXiv:2610.32578） | 陈旧文档占失败类 48/118；一次审计只找到约 50% 已知漂移，精度 ≥93% | 只能做「高精度抽样器」，需要机械锚点兜底 |
| 本仓库现状 | 健康分 100 分全部来自结构指标（链接 35 / 元数据 25 / 修订 20 / 孤儿 10 / 架构 10） | 满分不代表内容还对；需并行一条真值轴 |

**现有可复用资产**：控制头解析（`check-doc-control-sync.parse_frontmatter`）已是通用的「引用块 key: value」解析器，新增字段无需改解析器；`audit-doc-health.py` 已有 `evaluate_verdict` 单一判定出口（BK-0028），新增维度不会产生「PASS 与 REJECT 理由并存」。

## 2. 术语表（术语先行）

| 术语 | 定义 | 易混淆处 |
| :--- | :--- | :--- |
| **代码锚点** | 文档断言所依赖的仓库内路径（可含行区间），如 `src/api/routes.ts:120-168` | 不是「引用链接」，不参与断链扫描 |
| **复核于** | 该文档最近一次被人工/agent 确认与代码一致的时点，记 `YYYY-MM-DD / commit <sha>` | 不是「生效日期」，也不是「修订日期」 |
| **漂移** | 锚点文件在 `复核于` 的 commit 之后又被提交修改 | 不等于「文档过期」；漂移是**怀疑信号**，需人判断 |
| **结构分** | 现行 `total_score`（链接/元数据/修订/孤儿/架构） | 保持语义不变，不与真值分混算 |
| **真值分** | 新增独立维度：新鲜度（freshness） | 覆盖率单列，不折算成得分 |
| **覆盖度** | 声明了代码锚点的文档占比 | 覆盖度低时真值分**不颁发满分**，明确报「未启用」 |

## 3. 方案对比与裁决

| 方案 | 做法 | 优点 | 致命缺点 |
| :--- | :--- | :--- | :--- |
| **A 合并计分**（调研报告原文） | 把 100 分重分配：链接 25 / 元数据 20 / 修订 15 / 孤儿 5 / 架构 10 / 新鲜度 15 / 可回答性 10 | 单一分数，压力直接 | 全库当前零锚点 ⇒ 分数立刻跌到约 75 并触发 `--threshold 80` 阻断；为恢复满分必须一次性给所有文档补锚点，等于用门禁逼出一批**伪锚点**——与「真值」目标相反 |
| **B 双轴并置**（推荐） | 结构分语义不变；新增 `truth` 报告块与 `--require-truth` 可选门禁；新鲜度只对**声明锚点**的文档计分，覆盖度单列输出 | 零破坏迁移；老门禁行为不变；新增门禁可逐步收紧 | 两个分数需人读；须明确「未启用 ≠ 满分」 |
| **C 只加字段不检测** | 控制头加三字段，不做漂移计算 | 成本最低 | 又一条 feel-good 指标（调研报告点名批评） |

**裁决：方案 B。**

**对调研报告的两处显式偏离**（按「宣称与取证同宽」登记）：

1. **不合并计分**：报告 P0-3 的权重表在当前零锚点基线上会直接把健康分打到 ~75，属破坏性变更；改为双轴 + 可选门禁，并保留「迁移完成后合并」为 P1 议题（D-4）。
2. **不建「可回答性」空维度**：报告 P0-3 列了 10 分可回答性，其落地依赖 P2-8 的 golden task 集；本次**不建空指标**（避免零信息维度稀释真值轴），只登记为后续项（D-5）。

## 4. 契约

### 4.1 控制头三字段（可选，声明即受检）

```markdown
> - **来源**: raw/…（提案/决策类必填，其余可空）
> - **代码锚点**: src/api/routes.ts:120-168, src/models/user.ts
> - **复核于**: 2026-11-20 / commit a1b2c3d
```

- 字段缺失 ⇒ 该文档**不参与**新鲜度计分，计入「未声明」；
- `代码锚点` 允许逗号/顿号分隔；路径按**仓库根**解析，禁止 `..` 越界；
- `复核于` 的 commit 可省略（则退回按日期比较）。

### 4.2 `check-doc-drift.py`（新增）

| 项 | 契约 |
| :--- | :--- |
| 入参 | `--root docs`、`--repo .`、`--json`、`--fail-on-drift`、`--fail-on-unverified`、`--max-age-days N`（默认 180）、`--baseline`、`--write-baseline` |
| 判定 | 对每个文档：锚点存在性 → 锚点文件最近提交时间 vs `复核于` → 输出 `drifted / missing_anchor / stale / unverified / fresh`（优先级即此序） |
| 退出码 | `0` 无漂移（或未加 `--fail-on-drift`）；`1` 存在 drifted / **missing_anchor** / 基线墓碑违规（`--fail-on-unverified` 时再加 unverified / stale）；`2` 入参/环境错误（非 git 仓库、**浅克隆**等，fail-closed） |
| 未跟踪锚点 | 锚点文件存在但未被版本控制 ⇒ `unverified`（无提交时间可用，不得当 fresh） |
| 基线墓碑 | `--write-baseline` 把当前声明写入 `<root>/.doc-truth-baseline.json`；此后**删除或缩减**声明即违规——这是「删锚点洗绿」的唯一机械拦截（覆盖率下限只是辅助） |
| 豁免 | `project/reviews/**`（逐字凭据）、`archive/**`；根级入口文档（index/README/GOVERNANCE）**仅在未声明锚点时**不计入分母——声明了却排除会造成静默覆盖黑洞 |
| 幂等 | 默认路径**只读**；唯一写操作是显式的 --write-baseline（只写 <root>/.doc-truth-baseline.json） |
| 账本可用性 | 门禁模式（--fail-on-drift）下账本 missing/corrupt ⇒ **rc=2** fail-closed（「保护不可得」不得与「无违规」同形）；非门禁模式降级报告 |
| 空账本 | 结构合法但 docs 为空且存在已声明锚点 ⇒ 视同不可用（rc=2）——`{"docs":{}}` 一次编辑即可让墓碑失效，成本与删账本相同 |
| 改名/迁移 | 墓碑判据为**全局锚点多重集不减少**：纯改名/拆分合法；删文档、删锚点、缩减多锚点均违规。合法迁移用 --write-baseline 显式刷新并在提交信息登记 |
| 未来日期 | 「复核于」超前当前时间 1 天以上 ⇒ unverified（未来日期不是复核） |
| 锚点语义 | 文件或**目录**均可；含 glob/占位符（`* ? [] {} <>`）的锚点标记为不可机械核验 → `unverified`（不再一律 `missing_anchor` 硬红） |
| 门禁强度 | `--fail-on-drift` = **任何非 fresh 的已声明文档**（drifted / missing_anchor / stale / unverified / 墓碑违规）均 rc=1；`--allow-unverified` 显式豁免 stale/unverified |
| 墓碑归属 | 只归因到「自身声明数下降」的文档；共享同一锚点的未改动文档不再被连坐，同一路径只计一次 |

### 4.3 `audit-doc-health.py` 扩展

- 输出新增 `truth` 块：`{enabled, coverage, drifted, missing_anchor, unverified, freshness_score}`；
- `freshness_score = 15 × (已声明且无漂移 / 已声明)`，`已声明 = 0` 时置 `0` 并报 `not_enabled`；
- 默认 `--truth=warn`：**不改变** `total_score` 与 PASS 判定；`--truth=require` 按序判定三条：①「未启用」即阻断；②声明覆盖率低于 `--min-coverage`（默认 0.5）即阻断；③真值分低于 `--truth-threshold`（默认 12/15）即阻断；
- **同日复核语义**：`复核于` 只写日期时按**当日末刻**（23:59:59 UTC）起算，同日提交不算漂移；写了 commit 则以该提交时间为准；
- `--json` 向后兼容：只增键，不改既有键名。

## 7. 风险与回滚

| 风险 | 缓解 |
| :--- | :--- |
| 漂移误报（格式化提交也计入） | 只报「可疑」，不自动改文档；`--max-age-days` 与人工复核兜底 |
| git 不可用（CI 浅克隆） | `--repo` 探测失败返回 2（fail-closed），不静默通过 |
| 字段格式漂移 | 解析器容错 + AC-4 用例锁定「无复核于」的语义 |

## 8. 明确不做（Out of Scope）

分层 `llms.txt`、`docs/AGENTS.md`、检索层、矛盾状态扩展、并发软锁、golden task 评测——均属调研报告 P1/P2，另立 RFC。
