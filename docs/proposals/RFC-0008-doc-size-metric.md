## 1. 背景

本仓库同时存在两条互相矛盾的规范：

| 规范 | 内容 | 现状 |
| :--- | :--- | :--- |
| `SKILL.md` 负向规范 6 | 「单份文档原则上不得超过 800 行」 | **无任何门禁实现**（脚本命中 0 次） |
| Backlog 调研 D2 | 「行数度量失效：399 行 / 201KB / 最长单行 4,258 字符仍判合规」 | 已论证，但未落地 |

实测存量：

| 文档 | 行数 | 字节 | 最长单行 |
| :--- | ---: | ---: | ---: |
| `project/plans/2026-10-12-spec-evolution.md` | 2,359 | 127,747 | 879 |
| `project/plans/2026-10-19-skill-scripts-python-unification.md` | — | — | 1,269 |

**结论**：800 行这条红线既没实现、指标本身也已被否决。直接实现它等于给失效指标加锁；直接删除它等于放弃体量治理。正确动作是**换指标并补门禁**。

## 2. 术语

| 术语 | 定义 |
| :--- | :--- |
| **体量三指标** | 字节数、最长单行字符数、行数（行数降为 warn） |
| **棘轮基线** | 记录存量超限文档的当前值；只要不增长即放行，增长即阻断（只进不退） |
| **新增超限** | 基线中无记录、但当前已超阈值的文档 |

## 3. 方案对比与裁决

| 方案 | 做法 | 问题 |
| :--- | :--- | :--- |
| A 实现 800 行门禁 | 补行数检查 | 指标已证失效（399 行/201KB 仍合规） |
| B 只换指标不设基线 | 超阈值即阻断 | 存量 2 篇立刻 REJECT，逼出「为过门禁而硬拆」 |
| **C 换指标 + 棘轮基线**（推荐） | 三指标 + 基线记录存量 | 增量受控、存量可渐进消化 |
| D 删除体量红线 | 不做体量治理 | 放弃一条已被证明有效的约束（长文档确实伤检索与阅读） |

**裁决：方案 C。**

## 4. 契约

### 4.1 阈值（可配）

| 指标 | 默认阈值 | 级别 |
| :--- | ---: | :--- |
| 单文档字节数 | 65,536（64 KB） | **阻断** |
| 最长单行字符数 | 1,000 | **阻断** |
| 行数 | 800 | 警告（不阻断，因指标已证失效） |

### 4.2 棘轮基线 `docs/.doc-size-baseline.json`

```json
{"version": 1, "docs": {"project/plans/x.md": {"bytes": 127747, "longest_line": 879}}}
```

判定矩阵：

| 当前状态 | 基线 | 结果 |
| :--- | :--- | :--- |
| 全部达标 | 有/无 | ✅ 通过（若基线有记录，提示可清理） |
| 超限 | 无记录 | ⛔ 阻断（新增超限） |
| 超限 | 有记录且**未增长** | ⚠️ 警告（存量，允许渐进消化） |
| 超限 | 有记录但**已增长** | ⛔ 阻断（恶化） |

### 4.3 命令

```bash
# 生成/刷新基线（仅在明确接受存量时执行，须在提交信息登记原因）
python3 skills/doc-governance/scripts/audit-doc-health.py --root docs --repo . --write-size-baseline

# 常规体检（含体量门禁）
python3 skills/doc-governance/scripts/audit-doc-health.py --root docs --repo .
```

## 5. 验收用例

| # | 用例 | 期望 |
| :--- | :--- | :--- |
| AC-1 | 全库达标 | 零缺陷 |
| AC-2 | 新增超限文档（无基线） | 阻断 |
| AC-3 | 存量超限 + 基线未变 | 警告，不阻断 |
| AC-4 | 存量超限 + 基线已增长 | 阻断 |
| AC-5 | 基线损坏/缺失 | 视为无基线（新增超限一律阻断） |
| AC-6 | 行数超限但字节/单行达标 | 只警告 |
| AC-7 | 基线中的文档已达标 | 提示可清理基线，不阻断 |

## 6. 决策台账

| 编号 | 类型 | 条目 | 依据 |
| :--- | :--- | :--- | :--- |
| D-1 | 已决 | 用字节 + 最长单行替代行数作为阻断指标 | 本仓调研 D2 已论证行数失效 |
| D-2 | 已决 | 棘轮基线消化存量 | 存量 2 篇，硬拆成本高于收益 |
| D-3 | 已决 | 行数保留为 warn | 保留可见性，不制造假阳性 |
| D-4 | 默认假设 | 64 KB / 1000 字符 | 64 KB ≈ 32k 汉字 ≈ 16k token；1000 字符单行已超出正常阅读宽度 |
| D-5 | 已排除边界 | 不自动拆分文档 | 拆分是编辑决策，不是门禁能做的 |

## 7. 风险与回滚

| 风险 | 缓解 |
| :--- | :--- |
| 基线被当成「永久豁免」 | 基线值只降不升（增长即阻断）；文档达标后提示清理 |
| 阈值不合理 | 三个阈值均可配；先用默认值跑一轮看分布 |

回滚：删除基线文件并移除检查项即可；不涉及数据迁移。
