## 1. 背景与痛点

调研报告 §4.3 的核心判断：**LLM 写的内容会静默腐化，而「有争议」这件事目前没有任何机械位置可放**。

现状：

| 现象 | 后果 |
| :--- | :--- |
| 控制头 `文档状态` 只有 `Active` 一个实际取值（全库 6 处均为 Active） | 状态字段是装饰性的，不承载信息 |
| 文档被新版本取代后，旧文档仍是 `Active` | 读者（人与 agent）无法判断该信哪一份 |
| 两份文档结论冲突时，冲突只存在于人的记忆里 | 下次审计仍需读全文才能发现 |
| `reference/` 的「唯一真相源」承诺没有退役机制 | 真相源只增不减，最终互相矛盾 |

调研给出的失败率参考：自动文档审计只找到约 50% 的已知漂移（arXiv:2610.32578），**指望 LLM 自动发现矛盾不可靠**；但「把状态写进元数据」是纯机械的——审计从「读全文」降级为「看状态」。

## 2. 术语表（术语先行）

| 术语 | 定义 |
| :--- | :--- |
| **Active** | 当前有效，可作为真相源引用（缺省值） |
| **Contested** | 内容仍有效但存在**未决争议**；引用方需自行判断 |
| **Superseded** | 已被另一份文档取代；**不得**作为真相源引用 |
| **取代于** | Superseded 文档指向接替者的仓库内相对路径（必填） |
| **争议点** | Contested 文档的一句话争议描述（建议填，缺失不阻断） |

## 3. 方案对比与裁决

| 方案 | 做法 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **A 保持现状** | 只有 Active | 零改动 | 状态字段无信息量；冲突不可见 |
| **B 三态 + 机械判据**（推荐） | Active/Contested/Superseded + `取代于` 必填 + 引用检查 | 纯机械可判；不动存量 | 需人工在冲突发生时改状态 |
| **C 自动矛盾检测** | LLM 定期扫描全文找矛盾 | 无需人工标注 | 调研已证不可靠（召回 ~50%），且同源偏差无法排除 |
| **D 引入完整文档生命周期**（Draft/Review/Approved/Deprecated/Archived） | 五态以上 | 表达力强 | 状态迁移需要审批流；本仓库无此组织条件，属过度工程 |

**裁决：方案 B。** 只加「有争议」与「已被取代」两个**有机械后果**的状态，其余留在 Active。

## 4. 契约

### 4.1 控制头字段

```markdown
> - **文档状态**: Active | Contested | Superseded
> - **取代于**: ./new-doc.md            <!-- Superseded 必填，其余不得出现 -->
> - **争议点**: 一句话说明争议焦点      <!-- Contested 建议填 -->
```

- 缺省 `Active`（无该字段视同 Active，存量零破坏）；
- 取值不在三态内 ⇒ 缺陷（防手误写 `Deprecated` 等未定义状态）。

### 4.2 机械判据（全部可脚本判定）

| # | 判据 | 级别 |
| :--- | :--- | :--- |
| C-1 | 状态取值必须是 `Active` / `Contested` / `Superseded` 之一 | **阻断** |
| C-2 | `Superseded` 必须含 `取代于`，且目标文件存在、为 `.md`、非自身 | **阻断** |
| C-3 | `取代于` 只能出现在 `Superseded` 文档上（Active 出现即矛盾） | **阻断** |
| C-4 | `Active` 文档不得在正文中把 `Superseded` 文档当真相源引用（`[..](./x.md)` 形式） | 警告 |
| C-5 | `Contested` 文档若超过 90 天未更新（按修订历史**最新日期**，不假定表格升降序；可配） | 警告（列入未决冲突清单） |
| C-6 | `取代于` 必须是**仓库内相对路径**：绝对路径与**越出仓库根** ⇒ 阻断；根内 `../` 跨目录链与 `#锚点` 均允许 | **阻断** |
| C-7 | 隐式 Active（未写状态字段）携带 `取代于` ⇒ 阻断 | **阻断** |

**明确不做**：不检测「两份文档内容互相矛盾」——那需要语义判断，调研已证不可靠；本 RFC 只保证「人一旦标注，机械面就能拦住」。

### 4.3 审计输出

`audit-doc-health.py` 新增 `doc_status` 块：

```json
{
  "counts": {"Active": 40, "Contested": 1, "Superseded": 2},
  "contested": [{"doc": "x.md", "reason": "...", "age_days": 12}],
  "superseded": [{"doc": "old.md", "by": "./new.md"}],
  "issues": ["..."]
}
```

文本输出增一节「未决冲突清单」（Contested 文档 + 争议点 + 年龄），使审计从「读全文」降级为「看状态」。

### 4.4 与既有门禁的关系

- **不改变** `total_score` 权重（结构分语义不变）；
- C-1/C-2/C-3 进 `evaluate_verdict` 的阻断理由（与 `llms_map_issue` 同级）；
- C-4/C-5 只进报告，不阻断。

| 编号 | 类型 | 条目 | 依据 |

## 7. 风险与回滚

| 风险 | 缓解 |
| :--- | :--- |
| 人工忘记改状态 | Contested 时效告警（C-5）；`取代于` 强制填 |
| 状态被滥用为「免责声明」 | C-4 警告：Active 文档引用 Superseded 会被列出 |
| 回滚 | 删除三字段即回到 Active；门禁对无字段文档零判定 |

## 8. 明确不做（Out of Scope）

状态迁移审批流、自动矛盾检测、跨仓库状态同步、`Deprecated` 等扩展状态。
