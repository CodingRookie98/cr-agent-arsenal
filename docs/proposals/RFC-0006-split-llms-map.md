## 1. 背景与痛点

`docs/llms.txt` 当前 **21,810 字节 / 92 条**（实测），已从「精炼入口」退化为「全集清单」：

| 证据 | 数值 | 含义 |
| :--- | :--- | :--- |
| 本仓库实测 | 21.8 KB ≈ 5–6k token | 单次读取即占掉可观上下文预算 |
| 社区实测（二手【C】） | `llms-full.txt` 被模型内置抓取截断在 25–30k token 且不报错 | 超过阈值后**静默截断**，尾部条目形同不存在 |
| 前注册消融（arXiv:2607.04576【A】） | 能力足够的 agent **根本不读大索引**，直接推断页面位置 | 大索引对强 agent 无收益，对弱 agent 是负担 |
| Mintlify 分层实践（厂商自测【C】） | 任务快 52.1%、token 省 44.8% | 分层是当前唯一有量化收益的做法 |

**根因**：一个文件同时承担了两种职责——「告诉 agent 有哪些象限」与「列出全部 92 篇文档」。职责一旦合并，就只能随文档数线性膨胀。

## 2. 术语表（术语先行）

| 术语 | 定义 |
| :--- | :--- |
| **根机器地图** | `docs/llms.txt`，面向 agent 的**象限级入口**，只回答「去哪找」 |
| **象限子地图** | `docs/_llms/<section>.md`，面向 agent 的**全量条目清单**，回答「这个象限有哪些文档」 |
| **路由文件** | `docs/AGENTS.md`，≤30 行，只规定读取顺序与硬约束，不承载任何知识 |
| **体量预算** | 根机器地图的字节上限（默认 8192），超限即门禁失败 |
| **split 模式** | 生成器的分层输出模式；缺省（无 `--split`）仍为单文件，向后兼容 |

## 3. 方案对比与裁决

| 方案 | 做法 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **A 维持单文件** | 现状 | 零改动；agent 一次读全 | 随文档线性膨胀；超阈值静默截断；与「精炼入口」定位矛盾 |
| **B 纯入口分层**（推荐） | 根只列 6 个象限 + 篇数 + 子地图链接；全量下沉 `_llms/` | 根体量恒定（≈1–2 KB）；职责单一；扩展无上限 | agent 需两次读取才能拿到具体条目（多一跳） |
| **C 根保留 Top-N** | 根列 6 象限 + 每象限 Top 3–5 篇 + 子地图链接 | 常见入口零跳转 | 「谁进 Top N」没有客观判据，必然演变成人工维护争议；根体量仍随 N 增长 |

**裁决：方案 B。**

理由：根文件的价值是**导航**而非**检索**。方案 C 试图同时满足两种需求，代价是引入一个无法机械判定的排序规则——而这正是本仓库一贯拒绝的「feel-good 指标」。多一跳的成本可被路由文件（`docs/AGENTS.md`）的读取顺序约定吸收。

## 4. 契约

### 4.1 根机器地图 `docs/llms.txt`

```markdown
# <项目名> Machine-Readable Knowledge Base Map

> 本文件是**象限级入口**：只回答「去哪找」，不罗列全部文档。
> 读取顺序：本文件 → `_llms/<象限>.md` → 该象限 `index.md` → 正文。

## Proposals & RFCs (需求与设计孵化层) — 5 篇

- 全量清单：[proposals.md](./_llms/proposals.md)
- 象限索引：[proposals/index.md](./proposals/index.md)   <!-- 存在时才有此行 -->
```

- **每象限一节**，标题含篇数；至少给出「全量清单」链接；
- 象限为空则整节省略；
- 不得列出具体文档条目（否则重新膨胀）。

### 4.2 象限子地图 `docs/_llms/<section>.md`

```markdown
# Proposals & RFCs (需求与设计孵化层)

> 本文件由 `generate-llms-txt.py --split` 生成，请勿手改。
> 上级入口：[../llms.txt](../llms.txt)

- [RFC-0006: …](./…)：摘要…
```

- 条目格式与现行单文件模式**逐字一致**（`- [title](link): desc`），便于工具复用；
- 链接为**相对 docs 根**的路径（与根文件同基准），保证从任意位置解析一致。

### 4.3 生成器

| 项 | 契约 |
| :--- | :--- |
| 入参 | `--split`（分层）、`--max-root-bytes N`（**仅 `--split` 下默认 8192**；默认模式不设限，显式 0 关闭）、`--check`（只校验不写盘） |
| 输出 | 根 `llms.txt` + `_llms/<section>.md`；空象限删除对应子文件 |
| 幂等 | 固定排序、固定格式、无时间戳；同输入两次生成逐字节相同 |
| 排除 | `_llms/` 自身、`AGENTS.md`（路由文件不进地图）、交付凭据归档、`archive/` |
| 体量 | 根产物 > 生效上限 ⇒ **不落盘**并 exit 1，提示拆分子文件；上限只在 `--split` 下默认生效（默认模式保持旧语义，RFC §7 的回滚命令仍可用） |
| 落点 | 根文件写到 `--output` 的**完整路径**（含自定义基名）；子地图写到 `<output 目录>/_llms/` |
| 链接重写 | 描述内链接只对仓库内相对路径补 `../`；`http(s)`/`mailto`/任意 scheme/协议相对 `//host`/锚点一律不改写 |
| 兼容 | 无 `--split` 时行为与现行一致（单文件、逐字节同产物）；**唯一例外**：描述内若含 `//host` 协议相对 URL，S-4 修复后不再被改写成断链，故该类输入的产物与 V0.1.0 差 2 字节（有意偏差，真实 docs 无此输入） |

### 4.4 路由文件 `docs/AGENTS.md`

- **≤30 行**，只含三件事：读取顺序、硬约束（禁猜路径、禁手改生成物）、门禁命令；
- 不承载领域知识、不复制目录拓扑（复制即漂移源）；
- 由 `audit-doc-health.py` 断言行数上限与必需小节存在。

### 4.5 门禁扩展

| 门禁 | 扩展 |
| :--- | :--- |
| `check-doc-links.py` | 已扫描全部 `*.md` ⇒ `_llms/*.md` 自动纳入；根 `llms.txt` 的相对链接按所在目录解析（现行行为已覆盖） |
| `audit-doc-health.py` | 机器地图一致性改为**多文件比对**：根 + 全部子地图逐字节一致；子文件多余/缺失（含**嵌套目录**与**符号链接目录**）均判漂移；根体量 >8192 计入缺陷 |
| 检测/清理同口径 | `--check` 与写盘清理均用 `rglob` 递归，保证「照提示重生成」一定收敛（SD-1） |
| `generate-llms-txt.py --check` | CI 只读校验入口，不写盘 |

## 5. 验收用例

| # | 用例 | 期望 |
| :--- | :--- | :--- |
| AC-1 | 默认模式（无 `--split`）生成 | 产物与 RFC-0005 前**逐字节相同**（零破坏） |
| AC-2 | `--split` 生成 | 根 ≤8192 字节；6 个非空象限各有子文件 |
| AC-3 | 幂等 | 连续两次 `--split` 产物逐字节相同 |
| AC-4 | 空象限 | 该象限子文件被删除，根不出现该节 |
| AC-5 | 根体量超限 | 不落盘 + exit 1 + 提示拆分 |
| AC-6 | 子文件被手改 | `audit-doc-health` 判「机器地图不一致」并给出重生成命令 |
| AC-7 | 子文件缺失/多余 | 同上判漂移（多文件集合比对） |
| AC-8 | `docs/AGENTS.md` 超 30 行或缺必需小节 | audit 判缺陷 |

## 7. 风险与回滚

| 风险 | 缓解 |
| :--- | :--- |
| agent 需两次读取，弱模型可能停在根 | 路由文件写死读取顺序；根每节给「全量清单」显式链接 |
| 子地图与根不同步 | 多文件集合比对门禁（AC-6/7） |
| `_llms/` 被误当作象限目录 | 生成器与 audit 均显式排除；命名用下划线前缀 |
| 回滚 | 删除 `_llms/` + 以默认模式重生成根文件即可恢复单文件形态（一条命令） |

## 8. 明确不做（Out of Scope）

检索层与 MCP 服务、`llms-full.txt`、多语言子地图、按读者角色分层——均属后续 RFC。
