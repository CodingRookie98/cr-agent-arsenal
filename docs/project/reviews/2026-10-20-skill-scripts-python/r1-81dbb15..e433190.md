## 1. 第一性原理与本质溯源分析

### 1.1 改动性质定性

- **交付物**：8 个自建技能脚本（goal-state-tracker / dispatch-agy / check-decision-ledger / scaffold-doc / check-review-report / prepare-review-context / check-qa-report / generate-seed）各自新增同目录单一 `.py` 实现，原 `.sh` 退化为 5 行 POSIX 壳；13 个契约测试改为运行时无关；技能内文档与 4 个注册面同步。
- **本质根因**：8 个脚本的行为契约长期寄生在「bash + GNU awk/grep + locale」三重合体上——字段切分依赖 `IFS=$'\t' read` 的空字段折叠、空白判定依赖 gawk `[[:space:]]` 的 Unicode 语义、参数解析依赖 bash `getopts` 与 `set -u` 的报错文本。所谓「Bash 实现」其实只是这些外部程序语义的编排层。迁移到单文件 `.py` 的方向正确：消灭双实现，消除 POSIX-only 运行时依赖，其中 `goal-state-tracker.sh`（`exec python3 - "$@" <<'PY'`，345 行内嵌 Python）本就是「bash 外壳包 Python」，本轮是真正的根因修复。
- **关键隐患（第一性原理层面）**：验收口径把「与 81dbb15 的 Bash 实现逐字节等价」当成唯一 oracle，导致其余 6 个脚本的 `.py` 变成「GNU 工具语义的逐条复刻器」：`getopts` 的 `illegal option` 文案、`set -u` 的 `$2: unbound variable` 行号（dispatch-agy.py 复刻 bash 第 42/46/50/54 行）、`read` 的空字段折叠（check-review-report.py `_read_fields`）、`[[:space:]]` 的字符类。**复刻层本身就是新的缺陷面**——本报告 R1-01/R1-02/R1-03 三个阻断级/中级缺陷全部落在「复刻不完整」这一点上，而不是 Python 语言本身。若不做逐字节 oracle 约束，check 系列本可写成 ~60 行「读入 → 结构断言」的直白状态机；当前方案是为满足历史保真而反向增加复杂度，属于 spec 与工程最优解的结构性冲突，需要 R2 在「等价性 vs 可维护性」上明确取舍。

### 1.2 物理与业务一致性
