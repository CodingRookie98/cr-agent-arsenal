## 3. 红队攻击路径推演 (Concrete Failure Scenarios)

- **攻击路径 1: 净化落在判定路径上 → 合规仓库硬阻断假阳性 + 门禁反向改写项目身份（本区间最严重发现）**
  - **触发条件**: 维护者以公开参数 `--name` 生成地图，且项目名满足任一：(a) 长度 > 64 码点（例如 71 字符的描述性英文名 `CR Public Skills Arsenal for Multi-Agent Orchestration and Doc Governance`）；(b) 含首尾空白；(c) 含非 ASCII 空格 `Zs`（U+00A0 不换行空格、U+3000 表意空格，粘贴场景常见）；(d) 含 `Cf` 字符（emoji ZWJ 序列、U+200B、软连字符）。
  - **复现推演**: 隔离双树 base/head，各用**其自身真实的** `generate-llms-txt.py --name=<名>` 生成地图（`gen_rc=0`，H1 逐字记录该名）→ base 审计：反解原值即生成参数，`:128` 逐字节相等 → **PASS**；head 审计：`:107` 进 `_sanitize_project_name` → `:94` 删除/清空 → `:95` 超限回落 `System` → 以净化串再生成 → `:128` 逐字节不等 → 返回缺陷串 → `:684`/`:697`/`:711` 触发硬阻断 → **REJECT**。实测四类（`len65`、`cjk65` 即 65 个中文、`" Foo "`、`A[NBSP]B`）：**base 全 PASS，head 全 DRIFT_REJECT**。

| 名字类 | base 审计 | head 审计 | 结论 |
|:---|:---:|:---:|:---|
| `L×64`（边界内） | PASS | PASS | 无回归（边界选择本身可用） |
| `L×65` | **PASS** | **DRIFT_REJECT** | **本次引入的假阳性** |

  - **涉及代码**: `skills/doc-governance/scripts/audit-doc-health.py:94,95,107,118,128,133`；放大器 `:684,697,711`；既有回归网缺口 `skills/doc-governance/tests/test_doc_governance_scripts.py:1000-1009`（batch B 的 R1-2 用例只覆盖「≤64 且纯 ASCII」的自定义名，故本回归未被网住）。

- **攻击路径 2: 「删除」而非「归一化」→ 合法名被静默拼接，不同名收敛为同一身份**
  - **触发条件**: 名含非 ASCII 空白或 `Cf` 字符（`A[NBSP]B`、`A[ZWSP]B`、`A[ZWSP]B` 类）。
  - **复现推演**: `:94` 的 `"".join(ch for ch in raw if ch.isprintable())` 对 `Zs`（除 U+0020）与 `Cf` 返回 False → 字符被**删除而非替换为空格**：`A[NBSP]B` → `AB`、`A[ZWSP]B` → `AB`、`" Foo "` → `Foo`。实测提示分别输出 `--name=AB` / `--name=AB` / `--name=Foo`，修复后 H1 与之一致。
  - **影响结果**: 语义碰撞——`A[NBSP]B` 与 `AB` 经净化后不可区分；维护者按提示操作即静默接受改名，且**门禁不告知发生改写**。与 R1-1 同根因（同一净化位置）的不同观测面。
  - **涉及代码**: `skills/doc-governance/scripts/audit-doc-health.py:94-97`。

- **攻击路径 3: 新增 NUL 用例的断言恒真（不可伪证）→ D2-5 的 NUL 分支无回归网**

## 5. 第一轮结论概要

**裁决倾向：不予放行（1 个 P1 阻断项）。** 本区间呈现清晰的「一半本质、一半浅层」结构：
