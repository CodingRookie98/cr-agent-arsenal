## 4. 回归与假阳性评估

### 4.1 假阴性面（仍可洗绿，按可利用成本排序）

1. **删账本**（R2D-1）：`git rm docs/.doc-truth-baseline.json` 与删声明同一提交 ⇒ rc=0。成本 = 一次 `rm`，比修复前**更低**（修复前至少要逐篇删锚点行）。
2. **未来复核日**（R2D-3）：改一个日期字段 ⇒ 15.0 + PASS，成本 = 一次字符替换。
3. **不建账本**（R2D-1）：新仓库/新目录默认即处于无保护态，且门禁不提示。
4. **未跟踪锚点**（R2D-5）：DoD 命令 rc=0（状态已诚实，退出码未跟上）。

> 其中 1、3 属同一失效机理（「保护不可得」与「无违规」在退出码上同形），合并计一条 P1；2 是另一个独立面，P2。

### 4.2 假阳性面（误红，方向安全但会诱发「反射性洗白」）

| 触发 | 实测 | 定级 |
| :--- | :--- | :---: |
| 文档改名 / 拆分 / 归档 / 目录迁移 | F1–F4 全 rc=1 | R2D-2（P2） |
| glob / 散文 / 目录 / 占位符锚点 | E、P 全 rc=1 | R2D-6（P2） |
| 非标准 `--root`（如 `docs/explanation`） | audit 判 missing / 0.0，drift 判 fresh / 15.0 | R2D-4（P2） |
| 浅克隆 | audit 判 missing 2 / 0.0 且 PASS | R2D-4（P2） |

**关于「是否需要豁免/迁移机制」的正面回答（派发单第 4 问）**：
- **属实，需要**，且**不需要**新增豁免白名单——白名单本身就是第二个可洗绿的状态。
- 最小正解是**换判据**：墓碑只保证「**锚点多重集不减少**」，不保证「某个文档路径下仍写着某锚点」。这样改名/拆分/归档天然通过（锚点总量不变），而「删 2 条声明」仍被抓住（总量减少 2）。现有 `_removed_from_baseline` 只需把 `current_anchors` 先摊平为多重集再比对，**净增约 6 行、无新状态**。
- 若坚持按文档键比对，则必须给出 `--baseline-migrate` 之类的显式迁移动作，并在 PR 模板里要求「账本变更必须单独申报」——但这条**把责任推回人工**，与「机械门禁」的自述不符，故列为次选。
- **定级：P2**（方向 fail-closed；且现状下唯一的出路是 R2D-1 那条洗白命令，两者耦合后风险实际上是**P1 的一半**，见 §5.1 判定说明）。

### 4.3 判定梯一致性与 `--truth=warn` 惰性（派发单第 5 问）

**（1）打印侧与裁决侧是否真正共用 `truth_blockers()`——是，且已用变异证明**

在 `/tmp/r2d/mut` 复制整份 scripts 后，把 `truth_blockers` 的非 require 早退分支改为返回哨兵字符串，实跑：

| 场景 | 打印侧（💡 诊断段） | 裁决侧（🏁 结论段） |
| :--- | :--- | :--- |
| 变异体 + `--truth=warn` | `⛔ 真值轴阻断: MUTANT-真值阻断哨兵` | `🚫 REJECTED（MUTANT-真值阻断哨兵）` |
| 变异体 + `--truth=require` | 无（走真实梯） | `PASS`（该夹具无违规） |

⇒ 两处**同源同变**，R2-3（BK-0028 单一判定出口）**真解**。另有 J 场景的实态证据：墓碑 + 覆盖率**两条理由同时**在打印侧与 REJECTED 理由中按同一顺序逐字出现。

**（2）`--truth=warn` 是否完全不影响既有 PASS / 结构分——是**

| 命令 | 总得分 | 结论 | rc |

- `off` 与 `warn` 的输出**逐行 diff 仅差 1 个空行**（真值块整块），结构分、分项分、诊断理由、退出码全等。

> ## 🔴 **阻断交付（Blockers = 1 > 0）**
>
> **判定理由（一句话）**：R2 亲定的机械验收三条里，**两条真解**（未跟踪锚点 → `unverified`；硬断裂 → rc=1），第三条（墓碑）在账本在位时**确已闭合**，但整套拦截建立在一个**可缺席、可损坏、可被同提交删除的账本**上——这三条路径下门禁给出的结论与「从未违规」**在退出码上完全同形**（B5 实测：R2 当时的洗绿动作逐字重放，rc=0、require PASS、🌟完美、15.0）。同一脚本对「历史不可得」选择 rc=2 fail-closed，却对「保护不可得」选择 rc=0 fail-open，属同一提交内的自相矛盾；而 GOVERNANCE:96 把该机制称作「唯一机械拦截」时未声明这个前置条件，正是本项目「宣称与取证同宽」铁律所禁止的形态。
>
> **放行条件**：§5.2 一行级修复（账本不可得 ⇒ rc=2）+ 账本前置条件写入 GOVERNANCE/SKILL/矩阵 → 补回归用例 → 以新提交为基线再走一轮 Delta 定向复验，Blockers 归零后准予交付。**不下调为「有条件放行」**：修复面明确、无设计灰区，且当前状态与 R2 亲口判定为 P1 的「预提交门禁恒绿」属同一失效方向。

### 5.4 移交下一轮的三条残留风险

1. **账本自身成了新的攻击面与新的运维负担（结构性）**：R2 §1.4 曾以「账本会自己漂移、与只读契约冲突」为由拦截墓碑方案，本轮仍引入了它，并顺带产生 `--write-baseline` 这条一键洗白命令与「改名即违规」的永久误红。**若不换成「锚点多重集」判据，下一轮红队五分钟内会用 `--write-baseline` 复现一次完整洗绿**。
2. **真值轴仍是「自证 + 两条机械不变量」，其机械性弱于自述（方法论）**：洗绿只需改一个日期字段（R2D-3），漂移识别依赖 `复核于` 是否诚实；本轮交付的三份自证文档改用「日期 + commit」是正向进步，但门禁本身没有对「未来日期」「同日全掩」做任何校验。
3. **报告面与门禁面仍在两张纸上（可观测性）**：矩阵 DoD 指定的 `--truth=warn` 在墓碑违规时打印「🌟完美 / PASS / 15.0」（B3），浅克隆时打印具体 `missing 2 / 0.0`（G3）——**评审者读到的报告会主动掩盖门禁已知的缺陷**。数据都已在 `truth_block` 里（`removed_from_baseline` / `unavailable`），只是从未渲染。
