## 1. 第一性原理与本质溯源分析

### 1.1 架构方向评估（先定大面，再穿透缺陷）

从第一性原理审视，Wave 2A 将 `goal-loop` 从历史演化堆积的 9–10 补丁编号（`P-1` 至 `P5`）、365 行 0% 实战使用的正则状态脚本（`goal-state-tracker.py`）、两份僵尸模板与不可度量的 `HALF-OPEN / min(25%, 剩余÷3)` 伪运行时中剥离出来，收敛为 **`Align → Plan → Execute → Verify → Close`** 五主阶段与事件驱动落盘，**主架构方向完全正确**。

但在「瘦身替换」的执行层面，本次变更暴露出三类典型的**浅层替换与边界漏检病灶**：

1. **为了压进「≤120 行」预算而牺牲了 `pack-handoff.py` 的核心健壮性与全仓既有跨平台契约**：
   - 将原本用于「计划文件状态同步」的正则脚本替换为 `pack-handoff.py`（119 行）后，新脚本把正则解析复杂度转嫁到了「任务块抽取 + 摘要截断 + Git 交接打包」上，但为了凑进 120 行上限，将逻辑高度压缩进多条密集单行表达式，直接丢掉了**三项已在本仓库经历过真实事故沉淀的工程不变量**：
     - 全仓其余 15 个技能 Python 脚本（及被删旧脚本 `goal-state-tracker.py:109,298,336-337`）统一强制执行的 `sys.stdout/stderr.reconfigure(encoding="utf-8", newline="\n")` 与 `newline="\n"` 落盘契约——导致新脚本在 Windows（无论英文 `cp1252` 还是中文 `gbk`）连自家官方模板都无法跑通直接抛出 `UnicodeEncodeError`；
     - 刚刚在 Wave 0（`check-doc-drift.py:500`）修复过的中文文件名 `core.quotePath` 陷阱——导致 `review-pkg` 在中文仓库输出八进制转义乱码路径，直接击穿「文件指针交接」的核心定位；
     - Markdown 围栏状态不变量——`limit=35` 裸切片截断代码块导致未闭合围栏吞噬整段 `## 目标任务`，以及行首行内反引号击穿 `_fence_flags`。
2. **「任务 ID 匹配」未针对自家模板做真实端到端验证**：
   - `pack-handoff.py:63` 的正则边界集合漏掉左括号 `(` / `（`，却错误收录了层级编号连接符 `.` 与 `-`，形成**双向失效**：对自己配套交付的官方模板 `skills/goal-loop/templates/goal-plan-template.md:97`（`Task V-2（条件 · 仅前端产物交付）`）直接提取失败（Exit 1），而在存在 `1.1`/`1` 或 `E-1-a`/`E-1` 的计划中则会静默返回 Exit 0 并抽出**错误的任务**。
3. **五主阶段重编号未完成技能内部闭环，造成同一技能内阶段编号语义错位**：
   - `W2A-1` 计划白名单遗漏了被 `SKILL.md:52` 和 `stage-progression-protocol.md:77,80` 直接挂载的核心规程 `skills/goal-loop/references/testing-decision-matrix.md`。重构后 `stage-progression-protocol.md` 中「阶段 1 = Align，阶段 2 = Plan，阶段 4 = Verify（废除 3.5）」，而 `testing-decision-matrix.md` 仍写着「阶段 1 = 计划制定，阶段 2 = 拆解，阶段 3.5 = 集成验证」。同一技能内相同数字指向不同阶段，属于典型的半程重命名回归。
   - 类似地，`host-adapters.md:91` 合并条款后残留指向不存在「第 5 项」的悬空引用，`contexts/AGENTS.md:50` 同一改动行内保留了与 V3.0 矛盾的「双轨状态机」。

## 3. 红队攻击路径推演

所有攻击路径均已在隔离系统临时目录（`tempfile.TemporaryDirectory()`，未修改仓库任何文件）或只读命令行中实证复现：

### 攻击路径 1：官方模板直接击穿 `pack-handoff.py brief`（自家狗粮即刻报错）
- **步骤**：对本次刚重构的官方模板执行 `python3 skills/goal-loop/scripts/pack-handoff.py brief skills/goal-loop/templates/goal-plan-template.md --task V-2`（或 `--task "Task V-2"`）。
- **实测结果**：`rc=1`，stderr 输出 `ERROR: 未在计划文件中找到任务: V-2`。
- **机理**：模板第 97 行写作 `- [ ] **Task V-2（条件 · 仅前端产物交付）**: ...`，`V-2` 后紧跟全角左括号 `（`，而 `pack-handoff.py:63` 的 lookahead `(?=$|[\s.:：—–\-)\]）\*])` 仅收录右括号未收录左括号。

### 攻击路径 2：层级子任务前缀撞车导致静默错派任务（Silent Wrong-Task Dispatch）
- **步骤**：构造含 `- [ ] **Task 1.1**: Subtask 1.1` 在 `- [ ] **Task 1**: Real Task 1` 之前、以及 `- [ ] **Task E-1-a**: Subtask E-1-a` 在 `- [ ] **Task E-1**: Real Task E-1` 之前的计划文件，分别执行 `--task 1` 与 `--task E-1`。
- **实测结果**：两次调用均返回 **`rc=0`**，却分别抽出 `Task 1.1` 与 `Task E-1-a`，完全遗漏真正的 `Task 1` 与 `Task E-1`。
- **机理**：`pack-handoff.py:63` 无条件将 `.` 和 `-` 作为任务 ID 结束边界，导致父编号无条件前缀匹配先出现的子编号。执行子智能体按「文件指针」领到错误任务并开始改错文件。

### 攻击路径 3：`limit=35` 截断「测试策略」代码块 → 未闭合围栏吞噬整段 `## 目标任务`
- **步骤**：构造计划文件，在 `## 2. 测试策略与级别裁定` 中填入 29 条说明行 + 10 行 bash 围栏命令块（模仿官方模板 L70-75 的结构），后接 `## 3. 任务` 与 `Task E-1`，执行 `pack-handoff.py brief <plan> --task E-1`。
- **实测结果**：`rc=0`，输出中仅出现 1 个开启围栏（`fence_count: 1`，无闭合围栏），紧随其后的 `## 目标任务` 与整个 `Task E-1` 正文全部落入未闭合的 bash 代码块内部。
- **机理**：`_slice_block`（L50）直接 `buf[:limit]` 截断，既不感知截断处是否处于 `fenced` 状态，也不闭合已开启围栏。

### 攻击路径 4：Windows 默认编码（中文 GBK / 英文 cp1252）100% 崩溃
- **步骤**：
  1. 模拟中文 Windows 控制台：`PYTHONIOENCODING=gbk PYTHONUTF8=0 python3 skills/goal-loop/scripts/pack-handoff.py brief skills/goal-loop/templates/goal-plan-template.md --task E-1`；
  2. 模拟英文 Windows / GitHub Actions `windows-latest`：`PYTHONIOENCODING=cp1252 PYTHONUTF8=0 python3 ...`。
- **实测结果**：
  - `gbk` 下 `rc=1`：`UnicodeEncodeError: 'gbk' codec can't encode character '\U0001f680' in position 169`（官方模板 L21 含 `🚀`）；
  - `cp1252` 下 `rc=1`：`UnicodeEncodeError: 'charmap' codec can't encode characters in position 2-8`（脚本自身输出中文标题 `# 任务交接简报：` 即炸）。
- **机理**：遗漏了全仓其余 15 个 Python 脚本及原 `goal-state-tracker.py` 统一执行的 `sys.stdout/stderr.reconfigure(encoding="utf-8", newline="\n")`。

### 攻击路径 5：中文文件名八进制乱码 + Commit 消息反引号击穿审查包围栏
- **步骤**：在临时 Git 仓库中提交 `文档/中文变更.md`（commit message 为 `feat: add 中文 doc and` 接三反引号 `fence break`）与 `has` 接单反引号 `tick.txt`，执行 `pack-handoff.py review-pkg <base> <head>`。
- **实测结果**：
  - `## 变更文件清单` 输出 `- ` 接带双引号的八进制串 `"\346\226\207\346\241\243/\344\270\255\346\226\207\345\217\230\346\233\264.md"`，`## 变更统计` 同样乱码；
  - `## 提交清单` 中嵌入的三反引号直接提前破坏代码块结构，`has` + 反引号 + `tick.txt` 破坏行内代码包裹。

### 攻击路径 6：空 `--out ""` 静默吐全文 & 目录 `--out` / 缺失 `git` 裸崩 & 倒置区间静默空包
- **步骤与实测**：
  1. `brief <plan> --task E-1 --out ""` → **`rc=0`**，文件未写，整篇 98 字节简报倾泻到 stdout；
  2. `brief <plan> --task E-1 --out <existing_dir>` → `rc=1`，裸 `IsADirectoryError` Traceback；
  3. `PATH=/nonexistent review-pkg <base> <head>` → `rc=1`，裸 `FileNotFoundError: 'git'` Traceback；
  4. `review-pkg <head> <base>`（倒置区间）与 `review-pkg <head> <head>`（空区间）→ **`rc=0`**，静默生成 `(无提交)/(无差异)/(无变更文件)` 空审查包；
  5. 计划正文出现行首三反引号行内代码（三反引号包裹 `code` 后接 `inline`）→ `_fence_flags` 将后文全部误标为围栏内，`brief --task E-1` 返回 `rc=1` 任务丢失。
