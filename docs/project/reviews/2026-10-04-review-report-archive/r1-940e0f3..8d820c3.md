# 第一轮对抗审查报告 (Round 1 Red-Team Review Report)

## 1. 第一性原理与本质溯源分析

- **改动性质定性**: **架构演进为主 + 两处"纸面条款式创可贴"**。根因判断（§1.3「可重建的运行时状态」与「不可重建的交付凭据」被塞进同一个被 gitignore 的容器）是**正确的第一性原理诊断**，据此做的两层分离（`.review-context/` 留状态、`docs/project/reviews/` 存凭据）+ 指纹登记，方向正确、非布丁。但两处关键控制点是"声明了能力、未落地机制"：(a) **指纹被宣称能检出「转录失真」，而指纹由转录者本人计算，物理上无法证明与被审查者原文一致**；(b) **G2「进版本库」与「宿主优先后归档根」均无任何执行保障**（后者已在 RFC §7.3 A3 登记为默认假设，按范围锁定只作 P3 记录，不定级为缺陷）。

- **物理与业务一致性**:
  1. **分层是对的，但归档根选错了容器语义**。方案 A 把"不可重建的审计凭据"放进 `docs/`，理由是"复用 doc-governance 既有门禁"。实测该假设反向成立：归档产物**本身违反** doc-governance 的门禁基线（无控制头 → 元数据分扣减；`r1-*.md`/`r2-*.md` 无任何 markdown 入链 → 恒为孤儿；报告内任意一条相对链接 → `check-doc-links.py` 硬失败）。即：**凭证进了"会判你不合格并拒绝"的管辖域，却被要求不可修改（改了就得重算指纹）**。当前实测 `audit-doc-health.py --root docs` = **98.8/100**（19/20 合规、0/20 孤儿），而本次交付的计划检查点（`docs/project/plans/2026-10-04-review-report-archive.md:35`）宣称"健康度 100/100"——**交付物自身的 scaffold 已经把这个数字打下来了**，且每发起一次审查都会再次注入同类违规文件。
  2. **指纹锁的是"写盘之后"，不是"写盘之前"**。`sha256(转录结果) == 台账登记值` 是自证式校验：同一次会话内由同一主体写入并登记，通过率恒为 100%。它能检出"事后被改"与"整体截断导致必需区块缺失"，**检不出改写、压缩、选择性摘录**——而后者恰恰是 RFC §1.2 指控的原始病灶。这一条直接决定 G5「消除转录失真」是未兑现的。
  3. **回归风险为负**：既有 12 项 `prepare-review-context.sh` 契约测试原封未动，全量 `pytest skills/` 实测 **167 passed**，无跳过、无回归。

- **过度设计审计**:
  - **未发现投机性抽象**；`--slug` / `--archive-root` 双选项、退出码 0/1/2 是维持契约一致性的最小接口，合理。
  - **两套标题匹配语义并存且不一致**（`check-review-report.sh:190-196` 用"任意位置子串"判区块存在，`:213-218` 的 `section_ids` 却要求 `index($0,hdr)==1` 行首匹配），同一份报告"区块齐备"与"缺陷清单为空"可以同时为真——这是语义裂缝，不是简约。
  - **围栏状态机被复制了第二份**（`check-review-report.sh:101-103` 逐字复制自历史实现 `skills/frontend-qa-gate/scripts/check-qa-report.sh:88-96`），复制的同时把该手法的盲区（仅识别反引号围栏）一并复制。规划确实声明"对齐已验证实现"，属可辩护取舍，但代价是两个技能同时继承同一盲区。
  - **产物提前创建**：归档目录与索引在任何一轮审查发生之前就 scaffold（`prepare-review-context.sh:265-296`），审查中止则留下空索引 + 指向它的锚点。轻微，登记 P3。

## 3. 红队攻击路径推演 (Concrete Failure Scenarios)

- **攻击路径 1: 交付门禁在"阻断交付"裁决上打印 PASS（已实跑坐实）**
  - **触发条件**: 索引「终审裁决」字段的值不是裸的 `✅ 准予交付`，而是任何**包含**"准予交付"四字的其它串——包括 RFC §3.4 自己规定的占位符格式 `[🔴 阻断交付 | ✅ 准予交付 | 未定]`，或带解释的 `🔴 阻断交付（未达「准予交付」标准）`。
  - **复现推演**: 主智能体按 RFC §3.4 逐字保留字段模板 → `grep -F '**终审裁决**' | head -n 1` 取到该行 → `[[ "$VERDICT_LINE" != *"准予交付"* ]]` 为假 → `VERDICT_NOTE="终审裁决 准予交付"` → **exit 0、打印"结构校验通过 … 终审裁决 准予交付"**，而同一归档里的 R2 报告白纸黑字写着"🔴 阻断交付"。门禁**从不交叉核对 R2 报告内的「交付判定」**，只信索引自述。
  - **影响结果**: 两轮对抗的最终放行开关被一个否定式短语短路——审查结论为"阻断"的交付可以拿到"准予交付"的机械凭据并进入合并。
  - **涉及代码**: `skills/dual-round-review/scripts/check-review-report.sh:240-245`；契约来源 `docs/proposals/RFC-0001-review-report-archive.md:152`。
  - **实跑证据**（三例均为合法归档目录，rc 与输出逐字摘录）:
    ````text
    终审裁决 = "✅ 准予交付"                      -> rc=0 | 结构校验通过: ... · 终审裁决 准予交付
    终审裁决 = "[🔴 阻断交付 | ✅ 准予交付 | 未定]" -> rc=0 | 结构校验通过: ... · 终审裁决 准予交付   <-- RFC §3.4 原文
    终审裁决 = "🔴 阻断交付（未达「准予交付」标准）" -> rc=0 | 结构校验通过: ... · 终审裁决 准予交付   <-- 应为 rc=1
    ````

- **攻击路径 2: 空壳报告穿透"结构完整"门禁（已实跑坐实）**
  - **触发条件**: 只要报告文本里**出现过**8 个必需区块标题字符串即可，无需真实分节、无需任何缺陷行。
  - **复现推演**: 构造一份"报告"，全文只有一句话："本报告覆盖 ## 1. 第一性原理与本质溯源分析、## 2. 运行时与 SSR/沙盒安全推演、## 3. 红队攻击路径推演、## 4. 潜在缺陷清单 与 ## 5. 第一轮结论概要 五大区块（内容从略，无缺陷）"；R2 同理（三标题 + 零 ID 行）。`check_sections` 的 `grep -qF` 在**行内散文**中命中全部常量，`section_ids` 因 R2 表为空而无需任何 ID 对齐。
  - **影响结果**: `--require-verdict=PASS` **rc=0**，输出"区块齐备 · 稳定 ID 对齐"。门禁的成功文案向人类/编排者宣告了一个实际不存在的结构保证。
  - **旁证向量**（同一防护的第 2、3 条裂缝，均已实跑）：① `@~~~`@ 围栏不参与 `strip_fences`（仅匹配三个反引号），把 5 个区块连同表格整体放进 `@~~~`@ 代码块 → **rc=0**，RFC §3.5-7「防围栏伪造」被单个波浪号绕过；② `section_ids` 不做围栏剥离，R1 §4 中**仅写在围栏内**的 `R1-99` 可合法化 R2 裁决表里的 `R1-99` → **rc=0**。
  - **涉及代码**: `skills/dual-round-review/scripts/check-review-report.sh:101-103, 180-196, 213-218`；约束来源 `docs/proposals/RFC-0001-review-report-archive.md:174`。

- **攻击路径 3: 元审判整表吞掉 R1 阻断项（已实跑坐实）**
  - **触发条件**: R2 的「最终裁决明细表」不写任何 `R1-<n>` 行（空表或删光）。
  - **复现推演**: 删除 R2 表格中唯一一行 `| R1-1 | … |`，R1 报告的 P1 阻断项在 R2 完全消失。对齐逻辑只做 `R2 的 ID ⊆ R1 的 ID`（`check-review-report.sh:226-234`），空集恒满足 → **rc=0，"稳定 ID 对齐"**。
  - **影响结果**: 第一轮的每一个 Blocker 都可以在第二轮的机械层面被静默清空，而"两轮机械对齐"作为 G4 的卖点继续被打印。这是"审查结论可被撤销且不可追溯"的通道。
  - **涉及代码**: `skills/dual-round-review/scripts/check-review-report.sh:213-234`。

- **攻击路径 4: 归档产物反噬项目文档门禁（已实跑量化）**
  - **触发条件**: 任何一次真实审查完成归档后——即本特性**按设计正常运转**时。次要触发：某轮报告正文里出现一条相对 markdown 链接（如 `[SKILL.md](skills/dual-round-review/SKILL.md)`，从归档目录看是 404）。
  - **复现推演**: 在当前 docs 树 A/B 对照 → 保留 `docs/project/reviews/` 时元数据 **23.8/25（合规 19/20）**，移除该目录后 **25.0/25（合规 19/19）**，差异唯一来源就是归档索引；再模拟一次真实归档（索引 + r1 + r2 三文件）→ 扫描文件 20→23、**孤儿 0→2**（README.md 因文件名豁免，两份报告文件恒为孤儿）、断链 14→16；`check-doc-links.py` 与 `audit-doc-health.py` 在 REJECTED 时**退出码均为 1（硬失败）**。
  - **影响结果**: 门禁分值随每次交付单调衰减（`meta=25×合规/总数`、`orphan=10×(总数−孤儿)/总数`，归档产物恒为"无控制头 + 无入链"），而单条相对链接可让断链项 **35 分直接归零 → REJECTED（≈63.8 分）**，直接卡死后续交付的 L-Doc 门禁；要修复就得改动已被指纹固定的审计凭据。SKILL.md §1.6 与步骤 2/3 的归档动作里**没有任何一步运行或豁免文档门禁**。
  - **涉及代码**: `skills/dual-round-review/scripts/prepare-review-context.sh:81`（默认根 = docs 内）；`skills/dual-round-review/SKILL.md:108-121, 143, 159`；`docs/GOVERNANCE.md:71`（只补了拓扑行，未加扫描豁免规则）。

- **攻击路径 5: 跨交付单元归档目录静默合并（已实跑坐实）**
  - **触发条件**: 新交付单元的 slug 是既有目录 slug 的后缀（如先有 `review-report-archive`，新交付 slug = `archive`）。
  - **复现推演**: `resolve_archive_dir` 用 `ls -d "$root"/*-"$slug" | sort | tail -n 1` 做**后缀 glob** 命中，随后打印"📦 复用既有归档索引" → 两个交付单元共用同一目录、同一份 `交付单元` 字段仍写着旧 slug 的索引、同一本轮次台账。
  - **影响结果**: 违反 RFC §3.3「一个交付单元一个目录」；两个交付的审查轮次在同一台账内交织，审计可追溯性受损；且复用过程**不校验既有索引的 `交付单元` 是否等于请求的 slug**，完全静默。
  - **涉及代码**: `skills/dual-round-review/scripts/prepare-review-context.sh:13-21, 266-296`。
