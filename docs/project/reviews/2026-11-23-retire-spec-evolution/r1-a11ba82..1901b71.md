- **攻击路径 1: 纯标准库环境下 `_fallback_parse_frontmatter()` 假阴性漏放非法 YAML 与嵌套字段劫持**:
  - **触发条件**: 在仅安装 Python 标准库 + `pytest`、未安装 `PyYAML` 的环境（仓库在 `docs/tutorials/quick-start.md:33` 与 `RFC-0004` `N-4` 明文约定门禁零第三方依赖，`test_skill_surface_sentinels.py:22` 亦预设了 `ImportError` 降级分支）运行哨兵测试；或在 `SKILL.md` frontmatter 中使用未闭合引号、引号内未转义同种引号、Tab 缩进块标量、以及 `agentskills.io` 规范允许的 `metadata:` 嵌套 mapping。
  - **复现推演**:
    1. 写入 `description: "Use when "foo""` 或 `description: "unclosed` 或 `description: |\n\tfoo`：实测 `yaml.safe_load` 全部抛出 `ParserError`/`ScannerError`（会导致 `npx skills` 静默丢弃技能），但 `_fallback_parse_frontmatter` 因仅检查 `val[0] == val[-1]`（`:69-70`）或显式放行 `"\t"` 缩进（`:64`）而全部返回 `OK` 放行；
    2. 写入带注释合法 YAML `license: "MIT" # spdx` 或 `description: "Use when: foo" # note`：因 `val[-1]` 为 `'x'`/`'e'` 非 `'"'`，前者 `license` 变为 `'"MIT" # spdx'` 被误拒，后者落入 `else` 分支被 `UNQUOTED_COLON_SPACE_RX` 误杀；
    3. 写入合法嵌套 mapping `metadata:\n  name: wrong-nested`：`_fallback_parse_frontmatter` 无缩进层级隔离，直接以嵌套键 `name` 覆写顶层 `meta["name"]`（导致合法技能因 `name != dir_name` 失败，或顶层错误 `name` 被嵌套合法 `name` 洗白）；
    4. 写入多行块标量 `|`（如含换行）或含 `\"`/`''` 转义串：`:67` 用 `" ".join(...)` 丢弃 `\n`、`:70` 未反转义，在 1023/1024 边界与 `PyYAML` 计算出的 `len(desc)` 不一致；
