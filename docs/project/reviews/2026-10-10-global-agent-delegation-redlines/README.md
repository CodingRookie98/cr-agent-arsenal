## 流程教训（须随交付留存）

1. **规模判定先于流程选择**：纯文本/规则措辞改动应走 Fast Path（改 → 跑测试 → 给人看 diff），不得挂载为代码交付设计的对抗审查；本单元错在**第一轮回复里就主动建议了审查**，把一个咨询问题拖成 6 轮重型流程。
2. **Blockers = 0 后不得主动追加迭代**：第 3 轮已清零，编排侧主动采纳非阻断建议追加第 4、5 轮，第 5 轮引入真实 P1 —— 负收益。
3. **红队角色不适用于措辞打磨**：角色预设"必有缺陷"使每轮必然产出新 P2/P3，而自然语言措辞无"正确边界"，形成永不收敛的循环；"同一根因换形 5 次"的真因是**工具与对象不匹配**，不是缺陷在换形。
4. **采纳子智能体建议前必须独立核验**：第 4 轮逐字转写 R1 建议而未核验其断言（该建议自称"字节数基本持平"，实测 +148B），违反本单元自身写入全局的 Zero-Trust 红线 —— 自指检验失败。
5. **书面控制语不构成控制**：先前写下的"不得以第四种谓词重演"在第 5 轮被绕过，说明缺少机械门禁时控制语无效。
