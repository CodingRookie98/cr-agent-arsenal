## 1. 第一性原理与本质溯源分析

- **改动性质定性**: **主病灶为本质根因修复，但 G2 的"写入面"存在成体系的浅层修补特征，整体判定为「根因修复 + 未闭环的写入契约」。**
  - 治本成立的部分：tutorial 模板硬编码 `../how-to/index.md` 的 404 不是链接写错，而是"模板单方面假设了一份规范未定义、生成器不产出的索引"（RFC §1.1-1.2 的诊断准确）。方案 A 同时补规范（G1）、补生成侧（G2）、做条件降级（G3），并复用既有"目录即入口"门禁事实而不改判定语义（N2），方向正确。实测：干净树（docs + skills + .gitignore 完整拷贝）下六类型批量生成前后 `check-doc-links.py --root docs` 均为 rc=0、新增断链 0 条；六个托管索引 `check-doc-control-sync.py` rc=0。GI-1／GI-2／GI-3 在**顺序 happy path** 上确实成立。
  - 仍是"创可贴"的部分：新写入器（`manage-doc-index.py`）**声称**维护三条强不变式（幂等登记 GI-3、人工索引零改写 GI-4、版本联动 §3.2.5），但没有任何一条被"强制"——判据比契约宽、识别面比契约窄、写入后不复验、写入无互斥。本报告 6 条 P1/P2 全部是"缺少自检"而非"缺少功能"的派生品：
    1. 托管标记判据是**全文子串**，而契约要求"正文首行（H1 之后）作唯一判据"→ 人工索引被误判并改写（R1-1，GI-4 失效）；
    2. 象限入口识别只认 `index.md`，而契约（§3.1／§5.2／DA-4）明示 `index.md` 与 `README.md` 等价且"既有 README 入口则不生成"→ 凭空生成第二份索引（R1-3）；
    3. 版本号正则比门禁自身的 `normalize_version` 更严（不支持 `V1.0.0 (Draft)` 这类本仓库通行的版本行注记）→ 登记成功但永不升版、永不写修订行，且门禁全绿（R1-4）；
    4. 升版与插行是两次独立编辑且**无后置复验**，与校验器语法分歧时控制头升版而修订行不写 → 门禁 rc=1（R1-5）；
    5. `register` 不校验目标文件存在 → 一条"✅ 已登记"的命令即可制造 404 并击穿零容忍断链门禁（R1-6）；
    6. read-check-write 无锁、无原子替换，且 `ensure_index` 与 `register_doc` 对同一文件读两次（放大窗口）→ 并发静默丢更新（R1-9）。
  - 更关键的是**交付自身的门禁不变式被自证违反**：RFC G5 与计划 P3.5.2 要求"`audit-doc-health.py` 得分不下降"，实测基线树 100.0 分 → 交付树 99.5 分（孤儿 0 → 2），而计划 L-Doc 行已把"得分不下降"勾选为 [x]（提交态 2583210 即如此），审查期工作树更把 P3.1~P3.5.2 全部勾选并宣称"全绿"（R1-2）。

- **物理与业务一致性**: 该改动的物理本质是**给一批"被其他工具解析的文档"新增了一个写入器**。SSOT 是否安全，取决于三件事：写入器对目标文档语法的理解是否覆盖校验器的语法、写入后是否复验、并发写入是否有互斥。本次实现三项皆缺，于是出现"变更器/校验器语法分歧"与"判据/契约语义分歧"两类系统性漂移：
  - **判据宽于契约**：`MANAGED_MARKER in content`（全文任意位置）vs RFC §3.2.1「正文首行（H1 之后）…作为唯一判据」；且该标记字符串被 SKILL.md 与设计书**公开引用**，任何人都可能在人工索引里引用它。
  - **识别窄于契约**：`index.md` only vs §3.1／§5.2「`index.md` 或 `README.md`，在目录入口判定上等价」，以及 DA-4「若项目既有 README.md 入口则不生成」。
  - **写后不复验**：`bump_header_version` 与 `insert_revision_row` 各自独立成功/失败，函数返回值不参与决策（`insert_revision_row` 找不到表头直接 `return text`），登记仍然报 ✅；`register` 也不回读校验产物是否仍满足 GI-1/GI-2。
  - **无互斥**：无 `flock`、无临时文件 + `os.replace`，两读一写，丢更新概率实测 12%（默认尺寸）/80%（~300KB 索引）。
  - **审查期工作树漂移声明**：`docs/project/plans/2026-10-09-quadrant-index-convention.md` 在本次审查进行中（2026-10-09 11:18:58）被编排者于工作树就地修改且未提交（相对 2583210 为 12 insertions / 10 deletions）。因此本报告对该文件的引用区分两态：**提交态**（L-Doc [x]；Task P3.5.2 为 [ ]；Active Checkpoint 仍写"最新有效提交: 95863c9（分支基线，尚无本次提交）"）与**工作树态**（P3.1~P3.5.2 全 [x]，Active Checkpoint 宣称"✅ 全绿"）。G5 在两态下均不成立。
  - **过程性质**：G5 是**相对量**断言（"不下降"），但计划的基线记录只写了"health PASS"、未记录分数（计划 §4 探查记录 1），因此该断言从未被真正测量过——这是"以绝对阈值（PASS≥80）冒充相对不变式"的口径替换，AS-5 字面通过（99.5 ≥ 80）而 G5 失败。

- **过度设计审计**: **未发现投机性抽象或过度泛化，这一点必须如实计入。** `manage-doc-index.py` 196 行、纯标准库（`argparse`/`pathlib`/`re`）、与既有 `manage-backlog.py` 同构；无新依赖、无新 CLI 开关（N4 合规）；`--title`／`--kind`／`derive_title` 均有真实调用方，非投机参数。仅有两点可收敛：`ensure_index` 与 `register_doc` 对同一索引文件**重复读取**（冗余 I/O，同时是 R1-9 竞态窗口的放大器）；测试文件中的 `run_script` 辅助函数为死代码。真正的"过度"不在抽象层，而在**契约覆盖面**——把三条强不变式托付给一个无锁、无复验、无输入校验的单文件写入器。

- **已实证成立的部分（对冲本报告的攻击性，避免误伤）**:

## 3. 红队攻击路径推演 (Concrete Failure Scenarios)

- **攻击路径 1: 引用即托管 —— 人工索引被静默改写（GI-4 失效）**
  - **触发条件**: 某象限以人工 `index.md` 维护分流入口，正文以说明/示例形式出现托管标记字符串（例如"本索引为人工维护，故不含 XXXXX 标记"，或按 SKILL.md／设计书的写法在代码块中引用该标记）。
  - **复现推演**: `scaffold-doc.sh how-to X` → `heal_doc_index` → `manage-doc-index.py register` → `ensure_index` 读文件，`MANAGED_MARKER in content` 命中 → 返回 `exists-managed`（连"检测到人工索引"的提示都不会打印）→ `register_doc` 再次全文匹配命中 → 尾部追加 `- [X](./X.md) — HowTo`（若版本行正则命中还会再升版 + 插修订行）→ 写回。实测（EXP17）：`ensure` 打印"象限索引已存在（托管），无需变更"，`register` 退出码 0 打印"✅ 已登记"，人工文件 diff 新增一行。
  - **影响结果**: RFC GI-4「人工索引零改写（逐字节不变）」失效；人类拥有的文件被脚本逐步接管并持续注入内容；`check-doc-links.py`／`check-doc-control-sync.py` 均无法发现（两者只校验格式与版本，不校验"谁拥有这个文件"）。
  - **涉及代码**: `skills/doc-governance/scripts/manage-doc-index.py:122`、`:141`；契约 `docs/proposals/RFC-0003-quadrant-index-convention.md:94`；现有测试只覆盖"完全不含标记"的人工索引（`skills/doc-governance/tests/test_doc_index_convention.py` 的 `test_register_skips_manual_index`）。

- **攻击路径 2: README 入口象限被生成第二份索引（SSOT 分叉）**
  - **触发条件**: 某象限以 `README.md` 作为分流入口（RFC §3.1 表格与 §5.2 裁决明确承认其与 `index.md` 在"目录入口"判定上等价；N5 只要求"不改写 README.md"）。
  - **复现推演**: 目录内已有人工 `how-to/README.md`（真实清单：deployment/local-setup）且 `check-doc-links.py` rc=0 → `scaffold-doc.sh how-to new-guide` → `ensure_index` 只探测 `index.md` → 判定"不存在" → `mkdir` + 写托管骨架 → 登记 new-guide。实测（EXP2）：目录同时出现 README.md（3 条人工清单）与 index.md（只含 new-guide 的托管清单），link-check=0、control-sync=0，门禁彻底无感。随后 `scaffold-doc.sh tutorial t1` 因 index.md 已存在而渲染真实链接——托管索引反过来"赢得"了链接选择权。
  - **影响结果**: 一个目录出现两个互相竞争的分流入口且永久分叉：此后所有自动登记只进 index.md，人类阅读 README.md 永远看不到新文档；违反 RFC §7.3 DA-4「若项目既有 README.md 入口则不生成（N5）」与 §5.2 的等价裁决。
  - **涉及代码**: `manage-doc-index.py:119-124`（`index_file = root / dir_rel / "index.md"`，无 README 分支）；契约 `RFC-0003-quadrant-index-convention.md:85`、`:198`、`:249`。

- **攻击路径 3: ghost 登记 —— 一个错字把强制门禁染红（GI-1）**
  - **触发条件**: 直接调用 CLI（GOVERNANCE.md §3 与 SKILL.md 都把 `register` 作为对外发布的人工维护命令），文件名写错或指向尚未创建的文档；或 `--file` 传子路径但父目录不存在。
  - **复现推演**: `manage-doc-index.py register --root docs --dir how-to --file ghost.md --title Ghost --kind HowTo` → 无存在性校验 → 追加 `- [Ghost](./ghost.md) — HowTo` → 打印"✅ 已登记文档至象限索引"、退出码 0 → 随后 `check-doc-links.py --root docs` rc=1，报"目标路径不存在 (404 Not Found)"。实测（EXP4）完全一致。
  - **影响结果**: 零容忍断链门禁被一条"成功"命令击穿，CI 直接阻断；脚本自身的退出码契约（§3.3"0 = 成功或安全 no-op"）被违背——写入了一条必然 404 的记录，既不是成功也不是 no-op。
  - **涉及代码**: `manage-doc-index.py:151`（无条件追加）、`:188`（成功文案）；门禁 `check-doc-links.py:169-170`。
  - **与作者自述的关系**: 计划 §4 探查记录 5（11:18，晚于两次提交，且相对 2583210 未提交、仅存在于工作树）已自述 SH-1，但只框定为"`--file` 未校验 basename（传 `sub/x.md`）"。实测证明缺口**更宽**：任意不存在的 basename（`ghost.md`）同样触发，修复必须并案扩大到"存在性 + 相对 root 约束"。

- **攻击路径 4: 交付门禁自证失败 —— 新增两篇文档即孤儿（G5 违反）**
  - **触发条件**: 对基线提交直接运行 `python3 skills/doc-governance/scripts/audit-doc-health.py --root docs`。
  - **复现推演**: 用 `git archive 95863c9 docs` 还原基线树 → 41 篇 / 0 孤儿 / **100.0 分**；交付树 43 篇 / **2 孤儿** / **99.5 分**（孤儿项 10.0 → 9.5）。两篇孤儿为 `docs/proposals/RFC-0003-quadrant-index-convention.md` 与 `docs/project/plans/2026-10-09-quadrant-index-convention.md`：它们不被任何文档以 `.md` 相对链接引用，且 `docs/index.md` 未收录（该文件对既有 10 份计划 10/10 全部收录，本次新增计划是唯一缺席者）。而本次 diff 恰好改写了 `skills/doc-governance/references/change-impact-matrix.md` 中"文档拓扑变动 → 必须同步 `docs/index.md` + 四类受影响文件"这一行。
  - **影响结果**: RFC G5 与计划 Task P3.5.2／L-Doc「health 得分不下降」在交付基线上不成立。状态须区分：在提交 2583210 中，L-Doc 行已是 [x]（写明"得分不下降"），而 Task P3.5.2 仍为 [ ]、Active Checkpoint 仍停留在基线（"最新有效提交: 95863c9（分支基线，尚无本次提交）""基线全绿"）——计划自述尚未与提交对齐；审查进行中（11:18:58）编排者在工作树把 P3.1~P3.5.2 全部翻为 [x]，并把 Active Checkpoint 升格为"✅ 全绿（…本仓库 docs 三件套 rc=0 且 health PASS）"。无论取哪一态，"得分不下降"都是**未实测的相对量断言**（基线记录只写"41 md / health PASS"，从未记录分数，方法上不可判定），且工作树态与实测直接冲突。修复动作即计划中**尚未完成**的 Task P5.1（`docs/index.md` 收录 + `llms.txt` 重生成），须在放行前闭环并复测。
  - **涉及代码**: `docs/index.md`（未改）、上述两篇新增文档；口径 `docs/proposals/RFC-0003-quadrant-index-convention.md:65`、`docs/project/plans/2026-10-09-quadrant-index-convention.md:100`、`:155`、`:166`。
  - **严格边界（防误伤）**: AS-5 的字面口径是"三件套 rc=0 / 健康度 PASS"，交付仍满足（99.5 ≥ 80，三件套 rc=0）；被违反的是 RFC G5 与计划 P3.5.2 的"**不下降**"口径。两者互相冲突，需 R2 裁决以哪条为准，但 [x] 的勾选状态与实测不符这一点不存在争议。

- **攻击路径 5: 变更器/校验器语法分歧 —— 控制头升版而修订行不写（GI-2 染红）**
  - **触发条件**: 托管索引的修订表首列表头被人改成任何非"版本号"字样（例如 `| 版本 |`），标记保留。
  - **复现推演**: `register` → `HEADER_VERSION_RE` 命中控制头 → V1.0.0 → V1.0.1 → `insert_revision_row` 以 `line.strip().startswith("| 版本号")` 定位表头失败 → 直接 `return text`（静默不插行）→ 写入、退出码 0 → `check-doc-control-sync.py` 按"`### 修订历史` 段 + 两行表头"解析同一文件，得到最新修订 = 1.0.0 ≠ 控制头 1.0.1 → **rc=1**。实测（EXP6）一致。
  - **影响结果**: 一条"成功"的登记命令把版本联动门禁染红；`register` 对自身产物零后置校验。
  - **涉及代码**: `manage-doc-index.py:91`、`:147-150`；`skills/doc-governance/scripts/check-doc-control-sync.py:110-123`。
  - **同源更隐蔽变体（无门禁可测）**: 版本行带注记时（`V1.0.0 (Draft)`；本仓库设计书自身就是 `V1.3.0 (新增…)` 风格）`HEADER_VERSION_RE` 不命中 → 登记成功但**永不升版、永不写修订行**，且 `check-doc-control-sync.py` 仍 rc=0（实测 EXP5b）。即：内容被改写而版本留痕为零，门禁完全不可见。

- **攻击路径 6: 并行脚手架静默丢更新（登记丢失）**
  - **触发条件**: 同一象限的两篇文档被并行生成／并行登记（多智能体并行脚手架；本仓库工作流本身就以并行子智能体为常态）。
  - **复现推演**: 进程 A、B 同时 read `index.md` → 各自（可能）升版并追加自己的清单行 → 后写者整体覆盖先写者 → A 的登记静默消失，两个文档只产生一次版本升级。实测（EXP9：默认尺寸索引，100 轮）**12 轮丢失**一条登记；（EXP3：把索引扩大到约 300KB，窗口随文件增大，25 轮）**20 轮丢失**。两个进程都打印"✅ 已登记文档至象限索引"。
  - **影响结果**: 文档从清单中消失（人类不可发现，并在 `audit-doc-health.py` 中成为孤儿 → 连带拉低健康分），失败完全静默、无任何告警。
  - **涉及代码**: `manage-doc-index.py:136-152`（read-check-write，无 `flock`、无临时文件 + `os.replace`；`ensure_index` 与 `register_doc` 对同一文件读两次，进一步放大 TOCTOU 窗口）。
  - **边界声明**: RFC §7.3 DA-2 与计划 §2 第 4 步已显式排除并发场景（"豁免 L4 级并发/压力测试…无并发契约"），故本轮**不据此判阻断**。但 DA-2 的影响评估（"极端并发下可能出现重复行"）与实测不符：真实后果是**静默丢失登记**（而非重复行），且触发只需两个普通并行进程。若并行脚手架成为常态用法，本条须重新定级并加锁／原子替换。

- **攻击路径 7: --dir 越界写入 --root 之外**
  - **触发条件**: 直接调用 CLI 时 `--dir` 传入 `../..` 或绝对路径（`pathlib` 语义中绝对右操作数会丢弃 `--root`）。

  - **涉及代码**: `manage-doc-index.py:119`、`:126-130`。
