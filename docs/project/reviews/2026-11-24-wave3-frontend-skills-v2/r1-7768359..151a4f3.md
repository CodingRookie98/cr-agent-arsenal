## 3. 红队攻击路径推演
1. **正常业务输入触发假阳性阻断（R1-1，`check-qa-report.py:8,16-17,106,108,131,136,138`）**:
   - 触发条件：按 `acceptance-matrix.md:14,37-38,43,51`（及 `qa-evidence-template.json:20`）执行前端运行时验收后，在 `qa-evidence.json` 的 `steps`、`na_reason`、`human_signoff[].item` 或 `signer` 中写入合法描述，例如 `"Check scrollWidth <= innerWidth and height > 0"`、`"Check <button> focus state"`、`"Verify <input> has <label>"`、`"No <img> elements rendered"` 或 `"Alice <alice@example.com>"`。
   - 调用链推演：`_check_assertions` / `_check_human` 调用 `_ok_str(val)` → `_ok_str` 执行 `PLACEHOLDER_RE.search(val)`（`r"<(?:[^>\s][^>\n]*)?>"`）→ `<= innerWidth and height >`（因 `=` 满足 `[^>\s]`）、`<button>`、`<input>`、`<img>`、`<alice@example.com>` 均命中正则。
   - 影响结果：100% 合法且具备真实磁盘证据的 `qa-evidence.json` 在 `check-qa-report.py --require-verdict=PASS` 下被误判为占位符残留，强制返回 `Exit 1` 阻断交付（本轮已用 `python3` 实测复现：`error: V1/S1/A1/P1: steps missing or placeholder`）。同时注意 `PLACEHOLDER_RE` 亦未拦截 `< fill steps >`（`<` 后有空白）或 `TODO`/`TBD`，而会拦截空串 `<>`。
2. **非字符串/不可哈希 `status` 引发未捕获 `TypeError` 栈崩溃（R1-2，`check-qa-report.py:104,134`）**:
   - 触发条件：向 `check-qa-report.py` 传入语法合法的 JSON，其中 `automated_assertions[i].status` 或 `human_signoff[i].status` 为 JSON 数组或对象（如 `["passed"]` 或 `{"x": 1}`）。

   - 影响结果：抛出未捕获 `TypeError: unhashable type: 'list'`/`'dict'` 并中断校验与错误聚合（本轮已实测复现；因仍以非零状态退出，未形成门禁绕过）。
