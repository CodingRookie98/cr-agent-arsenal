## 3. 红队攻击路径推演 (Concrete Failure Scenarios)

- **攻击路径 1: 写侧无"可反解"不变量 —— 工具自铸只能人工 rm 才能逃出的 fail-closed 陷阱（BK-0030 ② 未实现）**
  - **触发条件**: 首次生成（目标地图不存在）时以 --name 传入含行分隔符的名：LF（U+000A）、U+2028、U+000B（VT）、U+0085（NEL）、CR。无需异常权限，纯公开参数。
  - **复现推演**: main() -> _resolve_outgoing_name() 命中 not out_path.exists() 分支（generate-llms-txt.py:171-172）**直接返回请求名，无任何反解断言** -> generate_llms_txt() 写盘，H1 变为 "# A" + 换行 + 剩余部分 -> rc=0。此后 audit 的 _resolve_project_name()（audit-doc-health.py:107-115）以 splitlines()[0] 只得 "# A" -> 反解失败 -> REJECTED；**任何**重生成路径都在闸门 regex 处 rc=1。实测（LF / U+2028 / U+000B）3 类 × 3 条路径（缺省 / 显式同名 / 显式 System）= 9/9 rc=1 且字节不变；矩阵中 U+0085、CR 亦为 REJECT；唯一可行通道 rm 后重生成（实测 rc=0）。U+2028 类尤其隐蔽：H1 原始字节完全"标准"，是 splitlines() 在该码点断开。
  - **影响结果**: SSOT 地图进入永久 REJECT 状态；audit 的建议文案"请先人工确认正确的项目名，再以显式 --name 重新生成后再提交"在该状态下**不可执行**（显式同名也被拒），操作者或智能体按文案重试必得 rc=1，形成死循环；唯一有效通道（先删除文件）只在生成器 stderr 出现。
  - **涉及代码**: skills/doc-governance/scripts/generate-llms-txt.py:171-172,183-191；skills/doc-governance/scripts/audit-doc-health.py:141-146。

- **攻击路径 2: 变异体逃逸 —— 新契约两条承重语义无任何机械防线（上一批"无条件拒绝全绿"教训的镜像面）**

  - **复现推演**: 隔离树内注入变异后跑 doc-governance 全量（89 例）：M4 把拒绝分支改为直接返回请求名 -> **89 passed**；M5 恢复 audit errors="replace" -> **89 passed**。对照有效：M1 无条件 sys.exit(1) -> 7 failed；M2 沿用改回落缺省 -> 2 failed；M3 生成器改 errors="replace" -> 1 failed；M6 整体拆除闸门 -> 3 failed。即：**放行侧与 fail-closed 侧已承重，唯独"拒绝异名"与"audit 严格解码"两侧零覆盖**。

  - **涉及代码**: skills/doc-governance/tests/test_doc_governance_scripts.py:1320-1347；generate-llms-txt.py:197-202；audit-doc-health.py:107-111；docs/GOVERNANCE.md:125。

- **攻击路径 3: 特权执行环境下 0200 分支整例跳过 —— BK-0030 ③ 的回归保护蒸发**
  - **触发条件**: 测试进程具备 CAP_DAC_OVERRIDE（CI/容器常以 root 运行），os.access(path, os.R_OK) 返回 True。
  - **复现推演**: tests:1355-1356 的 self.skipTest(...) 抛出 SkipTest -> **整条测试方法中止** -> 同方法后半段（1362-1366）的非 UTF-8 fail-closed 断言一并消失。实测：注入 M3 且令 os.access(R_OK)=True（特权模拟）时为 **1 skipped / 0 failed**；同一 M3 在非特权环境为 **1 failed**。断言顺序决定了"可跳过的那半段"恰好是唯一能打红 M3 的那半段。
  - **影响结果**: 被 BK-0030 ③ 显式要求保护的 fail-closed 行为，在最常见的容器化执行环境中失去机械保护；该用例在特权环境下给出"绿"的假象。
  - **涉及代码**: skills/doc-governance/tests/test_doc_governance_scripts.py:1349-1366。

- **攻击路径 4: exists() 取代 is_file() —— 非规则落点从"跳过闸门"变为无界读取，可致挂死/内存膨胀**
  - **触发条件**: --output 指向"存在但非普通文件"的路径（FIFO、字符设备），或自动化脚本以 /dev/urandom、/dev/null 之类做落点。
  - **复现推演**: 闸门首判由 is_file() 改为 exists()（generate-llms-txt.py:171）-> 对 /dev/urandom 执行 read_text() -> 无界读取；实测 5s 未返回（挂起）。A/B 反证：base 同命令 rc=0 立即返回，head 挂起。另 /dev/null：base rc=0 -> head rc=1（IndexError 分支）；目录落点：base 为 Traceback，head 为干净拒绝（此点为改进）。
  - **影响结果**: 把"拒绝"语义退化为"卡死"或"内存耗尽"，在 CI/自动化管道中不可中断；256MB 级既有地图实测闸门读入使子进程峰值 RSS 达 526MB（读全文模式为历史既有读法，本次未加重，但 exists() 把面扩大到了无界设备）。
  - **涉及代码**: skills/doc-governance/scripts/generate-llms-txt.py:171,174-181。

- **攻击路径 5: 沿用路径静默归一化 H1 行边界空白（身份名不变、行字节被改写）**
  - **触发条件**: 既有地图首行含前导缩进，或契约短语之后存在尾随空白（空格 / 制表 / U+00A0）。
  - **复现推演**: 反解前先做 head_line.strip()（generate-llms-txt.py:183），边界空白被剥离 -> 身份解析成功 -> requested is None 直接沿用（:194-195）-> 写盘 H1 变为无缩进/无尾随空白的标准形态。实测 5 类形态 rc=0、name_before == name_after、h1_kept=False（H1-NORMALIZED）。
  - **影响结果**: 契约 §4.1 第 3 条"不得归一化"的字面口径与实际行为存在差异；后果有限（该形态本就被一致性门禁判为漂移，归一化后反而收敛），但会侵蚀"沿用 = 原字节沿用"这一后续读者依赖的隐式不变量。
  - **涉及代码**: generate-llms-txt.py:183,194-195；docs/GOVERNANCE.md:126。

- **已实测证伪的攻击面（勿重复裁决）**: 硬链接指向既有地图 -> 同一 inode 读同一身份、写同一 inode，身份保持（安全）；硬链接指向归档文件 -> 首行不匹配契约即 fail-closed 拒绝（本次闸门顺带收紧了轴向归档的历史硬链接面）；NFC/NFD -> 比较为码点精确、无任何 Unicode 规范化，异形即拒绝（安全方向、无绕过）；符号链接指向既有地图 -> resolve 后读取同一文件、身份保持；巨大既有地图 -> 读全文（历史既有读法）、身份保持、无截断。
