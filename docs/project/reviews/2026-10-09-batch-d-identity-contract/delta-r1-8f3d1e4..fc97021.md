## 1. 第一性原理与本质溯源分析

- **改动性质定性**: **两处真根因修复 + 一处结构性消除 + 一次确实承重的回归网重建，但附赠一处新次生缺陷**。
  - **R1-21 是根因修复，不是补丁**：上一轮的问题是「R1-5 的原子写引入了一条未过归档闸门的**影子写入面**」。本轮没有给影子路径再加一道闸门（那只是补丁），而是用 \`tempfile.mkstemp(dir=同目录, prefix=<name>., suffix=.tmp)\` 让**影子路径这一存在前提直接消失**：写入目标不再由调用者可推导的名字决定。这是「消除问题」而非「缓解症状」，定性正确。
  - **O_EXCL 才是真正的防线，随机名只是纵深**：竞争的原始缺陷模型是「攻击者/遗留工件预置同名条目 ⇒ write_text 跟随软链」。\`mkstemp\` 的内部原语是 \`os.open(..., O_CREAT|O_EXCL)\`，即便把 \`_RandomNameSequence\` 换成**完全可预测**的序列（我实测替换为 PREDICT1/2/3…），预置的软链条目与预置的普通文件条目都被**跳过**（predicted_names_used=3），受害者字节不变、预置普通文件内容原样保留。因此「prefix 可预测部分是否仍可被预置」的答案是：可预置，但**不会被跟随、不会被打开、不会造成任何写入**；随机性只降低碰撞概率，不承担安全职责。
  - **R1-20 的补丁用上了审计自己已经算出的谓词**：\`name_resolved\` 与 \`_is_safely_displayable\` 组合出正确的分支选择，且生成器一行未改。实测 5 类「可反解但不可安全回显」输入在按处方执行后**身份逐字保留、复审计 100.0 分 PASS**（详见 (b) 行）；分支 1 仍独立可达（3/3 实测）。上一轮「处方把用户从唯一无损通道劝离」的错误前提句确已删除。
  - **但本轮修复自身引入了新的权限语义**：\`mkstemp\` 固定以 0600 创建，\`os.replace\` 保留源文件模式位 ⇒ 最终地图从旧码的 0644 变成 0600。这不是「复位到标准位」（R1-25 记录的 0640→0644），而是**强制最小可读**：实测已提交的 \`docs/llms.txt\`（0644）经新码重生成后内容逐字节幂等、权限却降为 0600；实仓工作树同类文件现为 600 而 \`index.md\` / \`GOVERNANCE.md\` 为 644。修复的「不可预测唯一名」目标达成，但代价未被登记、未被测试、且对 git 完全不可见。
- **物理与业务一致性**: 归档红线这一侧，写入面已闭合到「可对抗完全可预测的名字序列」（见上）；输出侧的非规则文件、归档锚定软链（\`--output\` 解析后落入归档 ⇒ rc=1 拒绝，实测凭据不动）也保持完好；硬链接到凭据的输出落点被 \`os.replace\` 换 inode 而非写穿（实测 \`cred_inode_shared=False\`、凭据不变），即原子替换在该场景**优于**写穿语义。真正与既有承诺不一致的是**可读性**：地图是 git 跟踪的公开知识入口，0600 使「其他主体（CI 另一 uid、共享检出、容器非属主用户）读取 SSOT 地图」这一业务前提在跨主体场景下失效，且失败表现为审计自己给出的「机器地图一致性检查无法完成: Permission denied」**假 REJECT**（实测），而非可理解的权限提示。
- **过度设计审计**: **零过度设计**。生产代码净增 12 行；未引入独立脚本层、裁决语义解析器、\`.docignore\` 机制或任何共享模块重构；\`contextlib\` 与 \`tempfile\` 均为标准库且各被真实使用 1 处（无死导入、无死代码）；修改文件仅 3 个、无新增文件。清理分支（\`except BaseException\` + \`contextlib.suppress(OSError)\` + \`unlink\`）不是投机性容错，而是承重件：删除它后新用例立刻打红（M6）；把 \`OSError\` / \`KeyboardInterrupt\` 注入 \`os.replace\` 后残 file 均为 0，且注入了并非 \`Exception\` 子类的 \`KeyboardInterrupt\` 仍被正确清理并外抛，证明 \`BaseException\` 的选择是必要的。唯一「最小化不足」是**未显式设置临时文件权限位**（见 R1-27），而非抽象过多。
