## 1. 背景与动机

### 1.1 触发事件

2026-10-10，一次 **9 行**的全局提示词改动被挂载了 `dual-round-review` 完整流程：**6 轮**独立子智能体对抗审查、**6 份报告共 216KB**、6 次提交。用户判语：

> 「我感觉在整个工作你在矫枉过正，过度思考和过度形式化，太过机械化执行」

复盘出的失控点：① 编排侧在第一轮就主动建议了审查；② 第 3 轮已判 `Blockers = 0` 后仍主动追加两轮，**第 5 轮反而引入了一个真实 P1**——过度流程制造了缺陷；③ 红队角色预设"必有缺陷"，而自然语言措辞无"正确边界"，永不收敛。

### 1.2 社区与官方调研结论（三条）

1. **AGENTS.md 的头号失败模式是"出问题就加一条"**。[AI Hero](https://www.aihero.dev/a-complete-guide-to-agents-md) 称之为 *ball of mud*：agent 做了你不喜欢的事 → 你加一条规则 → 重复数百次 → 文件变成泥球。其判据是：**只有"每个任务都适用"的内容才配留在 root**。
2. **指令数增加会均匀削弱所有指令的遵循度**。[HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md)（引 arXiv 2507.11538）：前沿思考模型能稳定遵循约 150–200 条指令，Claude Code 系统提示已占约 50 条；**"instruction-following quality decreases uniformly"**。且宿主注入 AGENTS.md 时自带 *"you should not respond to this context unless it is highly relevant"*——**非普遍适用内容越多，整个文件越容易被忽略**。建议 <300 行，其自身 root 文件 <60 行。
3. **程序性内容应变成技能**。[Claude Code 官方](https://code.claude.com/docs/en/skills)：当 `CLAUDE.md` 中 *"a section has grown into a procedure rather than a fact"* 时，它就该是技能；而**"必须每次都成立"的规则应进 hook**（纯提示词是弱强制）。

### 1.3 核心洞察

本次失控**不是条款缺失，而是条款过载**——`dual-round-review` 技能的「无需触发」条目早已写明"纯文案调整…无需触发"，规则早就说了不该跑。因此本次重构的方向是 **减**，不是加；新增条款只会进一步摊薄既有条款的遵循度。
