## 4. 实施去向与结项记录
### 实施记录（2026-11-19）

**D1-7（PASS/REJECT 双真源）→ 单一真源**：新增 `evaluate_verdict(res, threshold) -> (passed, reasons)`，把五个判定条件只写一次；PASS 打印与 REJECT 理由清单都从它的返回值出。此前两条分支各自重算同一批条件，漂移即出现「既满足 PASS 又给出 REJECT 原因」的自相矛盾。

**D1-8（双读 TOCTOU）→ 单次快照**：`check_llms_map_consistency` 先 `read_bytes()` 取一次快照，名字反解与逐字节比对都用它；`_resolve_project_name` 改为接收文本，严格 UTF-8 解码留在调用方（BK-0031 语义不变：解码失败即 `resolved=False`，不下发任何 `--name`）。

**D2-2（无地图守卫零覆盖）→ 承重用例**：`test_no_map_with_indexable_docs_is_not_a_defect`——有可收录文档但无 `llms.txt` 时判必须返回空串；删守卫后生成器产出 N>0 并与缺失文件比对，该用例即转红。

**D2-1（written==0 分支不可达）→ 承重用例**：`test_zero_indexable_docs_with_existing_map_is_skipped`——地图存在但可收录文档为 0 时走「零覆盖态跳过」；删 written==0 守卫后必然报不一致，而提示的修复命令恒 rc=1（死胡同，BK-0027 登记）。

**D1-7 断言**：`test_verdict_single_source_*` 两条，钉住「五个失败项 ⇒ 五条理由」与「PASS ⇒ 理由为空」。

**未做（超出本卡 DoD，如实留痕）**：D1-5/D1-6（反解正则幂等、项目名自证循环）未逐条复验，也未改动；若要收口需另立卡并给出可复现的反例。
