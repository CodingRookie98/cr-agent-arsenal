## 1. 背景与上下文 (Context and Problem Statement)

RFC-0001 把审查报告的写盘责任判给**主智能体**，并自认其信任边界：

> 指纹由转录者本人计算登记，属自证式校验，**检不出**转录期的改写、压缩与选择性摘录。

结构化根因是 **内容作者没有写盘权、写盘者无法自证忠实**：报告的作者是子智能体，写盘者与指纹计算者都是主智能体，SHA256 只能证明「落盘之后未被改动」，不能证明「落盘内容等于作者的原始返回」。RFC-0001 曾把该残差转嫁给「R2 文件通道」——但 R2 读到的归档文件本身就是转录产物，缺口并未闭合。

RFC-0001 §7.3 A1 已把替代路径连成本一起预留：

> 若实测转录失真频繁，改为授权子智能体写报告文件（**需为 Read-Only 约束开例外并做路径预授权**），估算 +0.5 天

**硬性约束**：`dual-round-review` 是 `npx skills add` 分发的**宿主无关资产**，不掌握宿主沙箱；决策不得假设存在路径级强制能力。

## 2. 考虑的备选方案 (Considered Options)

* **方案 A（选定）**: 子智能体直写 + 路径预授权 + 双通道（`direct` / `transcribed`）登记
* **方案 B（未采纳）**: 维持现状，仅强化转录纪律
* **方案 C（未采纳）**: 引入外部签名/时间戳工具链作为独立写入进程

---

## 3. 最终决策与裁决 (Decision Outcome)

选定 **方案 A**：R1/R2 子智能体的 Write-Scope 约束开**唯一例外**——作者本人将报告原文直写至主智能体预授权的目标路径；主智能体由「转录者」转为「核验者」，独立复算 SHA256 并与子智能体回报值比对后登记；无写能力宿主保留**转录降级**通道，并必须在轮次台账新增的「写入形态」列显式登记 `direct` / `transcribed`；门禁追加第 8 项校验该列的存在与合法性。

### 3.1 积极后果 (Positive Consequences)

* ✅ **转录环节被消除**：报告原文不经主智能体之手，R1/R2 的推理链、攻击路径推演与 `文件:行` 证据按作者原样落盘
* ✅ **写盘与核验分离**：主智能体必须**独立复算**指纹；替换文件内容需同步伪造回报值，该伪造本身即越出 §3.7 的写入例外
* ✅ **降级从静默变为显式**：静默转录（RFC-0001 时代无法察觉）被「写入形态」列与门禁第 8 项暴露为可审计事实
* ✅ **R2 获得独立性依据**：R2 可直接核验 R1 报告的产出通道，对 `transcribed` 轮次显式降低采信度
* ✅ **改动面收敛**：载体仅 4 处（SKILL.md / 两个提示词模板 / 两个脚本），复用既有 scaffold 与 `sha256sum`，零新增依赖

### 3.2 消极后果与已知代价 (Negative Consequences / Trade-offs)

* ⚠️ **子智能体写入授权面从「零」扩大为「单个文件」**：这是本决策最实质的安全代价。在具备路径级隔离能力的宿主上它是可强制的收窄授权；在**不具备**该能力的宿主上，实际能力不变，约束强度等同于提示词自律。**技能文档必须按宿主能力分级描述，严禁表述为「已隔离」。**
* ⚠️ **「写入形态」列的声明不可机械验证**：它的价值是**可审计性**（暴露降级）而非**可验证性**。若把它当作「报告确由子智能体所写」的证明，即制造虚假安全感。
* ⚠️ **拒绝宽容旧表头引入破坏性影响**：V2.1.0 的六列台账在新门禁下判失败（第 8 项缺列）。这是刻意选择——若对旧表头宽容跳过，就留下「删掉表头即绕过登记」的后门。代价是既有归档需一次性补列迁移，且**分发到第三方项目后同样需要迁移指引**。
* ⚠️ **自证边界未完全消除，只是抬高**：从「单人自证」变为「需要主智能体与子智能体串通」，且主智能体仍掌握台账登记权。

## 4. 备选方案详细对比与论证 (Pros and Cons of the Options)

### 4.1 方案 A: 子智能体直写 + 路径预授权（选定）

* 概况: 作者写自己的内容；主智能体核验而非转录；双通道显式登记
* **选定理由**: 直接消除转录环节这一**结构性**失真源；改动集中在提示词契约与台账 schema，脚本改动面小；降级通道保住宿主无关性

### 4.2 方案 B: 维持现状，仅强化转录纪律

* **未采纳理由**: 这正是 RFC-0001 §3.7 已存在的状态，其残差已被 ADR-0001 §3.2 实证登记。「强化纪律」不是可验证的机制改进，属于把结构问题降级为态度问题

### 4.3 方案 C: 外部签名/时间戳工具链

* **未采纳理由**: 引入外部依赖与密钥管理，把「审查归档」变成需要运维的基础设施；且签名解决的是「谁写的」，不解决「内容是否等于作者返回」——后者靠直写即可消除。投入产出比不成立
