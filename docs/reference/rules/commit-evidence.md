## 1. 问题

提交信息的「取证」行同时承担两类内容：**可长期复核的结论**（门禁退出码）与**只有当次成立的测量值**（耗时、用例计数、findings 计数、文件权限）。复核者按「宣称与取证同宽」逐项复测时，后一类必然不可复现——同一根因因此反复触发阻断与更正提交（BK-0039 §5、BK-0042 §5 的更正记录即此形态）。

## 2. 规则

**R1 · 可复核的结论直接写。** 门禁退出码（`pytest rc=0`、`judge blocker/high=0`）这类「用一条命令能在同一棵树上复现」的结论，可以原样写入提交信息。

**R2 · 数字必须给出可复现的命令并落盘。** 若要写具体数字（用例计数、findings 计数），必须同时给出命令，并把原始输出落盘留痕（临时文件、CI 日志，或提交信息内附命令）；无命令的数字不得写入。

**R3 · 一次测量必须标注。** 耗时等浮动量须写成「一次测量」并给区间或多点采样，例如 `pytest 全量 ≈2.5–4.5 分钟（一次测量，本机）`；禁止写成 `耗时 2:47` 这类常数性事实。

**R4 · 不可复核属性不得作为完成度宣称。** 文件权限、工作区脏净、本机环境变量等 git 无法复核的属性，不得用来支撑「已完成 / 已验证」的结论。

**R5 · 历史更正不回改。** 已推送的历史提交与其更正记录保持原貌；本规则只约束此后提交。

## 3. 与既有不变式的关系

本文件是 [`contexts/AGENTS.md`](../../../contexts/AGENTS.md) §2「宣称与取证同宽（Evidence-Bounded Claims）」的**操作化细则**：不新增原则、不扩大管辖。原则说「未取证部分必须标注未验证」，本文件回答「哪些内容算取证、怎么写才可复核」。

## 4. 适用范围与反模式

适用于全部提交信息、审查报告与交付宣告。审查侧据此判定「宣称是否过宽」。

**刻意不引入提交信息校验脚本**：自然语言断言无法可靠机械化，脚本化只会产生假阳性并诱导作者规避措辞（改写同义句即可绕过），把「诚实披露」异化成「措辞游戏」。判定留在审查侧，但判定依据从「感觉」变成这份可引用的成文规则。
