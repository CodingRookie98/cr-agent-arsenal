# 回流路由表 (Regression Routing)

> 定位：当 `qa-evidence.json` 存在 `failed` 断言或 `runtime_signals` 异常时，规定**在哪里修、怎么重验**，防结构缺陷打浅层补丁或代码根因反复重排视觉。

---

## 1. 路由判定顺序

```text
缺陷出现（failed / runtime_signals > 0 / human_signoff failed）
  ├─ 方向级/品味级争议？ → 升级人类创意总监裁决
  ├─ 根因在源码实现（hydration/竞态/泄漏/派生状态）？ → 转 dual-round-review
  ├─ 真实视口布局崩坏或层级重排（结构类）？ → 回 taste-driven-designer D2
  └─ 其余产物行为缺口（行为修复类） → 就地修正 + 重验受影响断言
```

---

## 2. 四向回流路由表

| 缺陷类型 | 典型例子 | 修复位置 | 回流目标与重验路径 |
|---|---|---|---|
| **行为修复类** | 缺 `aria-label`、断点微调、焦点样式、错误/空/加载态补齐、触控目标过小 | 当前实现 | 就地修正 → 重跑受影响断言更新 `qa-evidence.json` |
| **结构类** | 真实视口布局崩坏、需重排信息层级或组件拆分错位 | 设计侧 | 回 `taste-driven-designer` **D2** → D3 后重验 |
| **根因类** | hydration 失配、异步竞态、资源泄漏、浅层修补掩盖失真 | 代码侧 | 转 `dual-round-review` 审查修复 → 回到本技能重验 |
| **方向级** | 文案语气、视觉装饰或交互取舍分歧 | 创意总监 | 升级人类裁决并记入摘要待决项 |
| **安全类（超范围）** | XSS、凭据/PII 落盘、依赖投毒 | 宿主 CI | 记录现象 + 标「超出本技能范围」+ 升级权限流程 |

---

## 3. 与 `dual-round-review` 交接与升级纪律

转出根因类缺陷须附 4 项最小上下文：① 现象与复现步骤；② 失败断言 `id`、`runtime_signals` 与证据路径；③ 怀疑模块范围；④ 已排除假设。引用失败模式库**仅写编号与名称**（如模式 1 浅层打补丁、模式 3 隐蔽异步竞态、模式 5 资源泄漏、模式 11 运行时与 SSR 沙盒盲区），严禁复制正文。

- 同一断言连续 **2 轮**以「行为修复类」失败时，强制升级为结构类或根因类复核；
- 路由明细记录于 [qa-summary-template.md](../templates/qa-summary-template.md)，状态取 `待分流 | 修复中 | 已重验通过 | 已升级人类 | 超出范围`。
