# 全向文档联动复核矩阵 (Documentation Synchronization Matrix)

## 概述 (Overview)

代码的演进必须伴随文档的实时同步更新。在大模型研发闭环中，最容易出现的坏味道是**“代码实现已大改，而文档停留在旧版本”**，导致后续维护者与下游智能体产生严重认知幻觉。
在 `goal-loop` 的**阶段 5（文档全向归档）**中，智能体必须对照本矩阵逐项复核并同步更新所有受影响的文档。

## 1. 文档全向联动检查清单 (Audit Checklist)

### 1.1 开发与架构文档 (Development & Architecture Docs)
| 文档类别 | 触发检查条件 | 典型检查路径范例 | 核心核验更新内容 |
|---|---|---|---|
| **架构设计规范** | 是否新增/废弃了模块、修改了系统分层、重构了核心调用链路 | `docs/architecture/*.md`, `docs/design/*.md` | 更新组件拓扑图、调用时序图与模块边界说明 |
| **数据契约与模型** | 是否调整了数据库 Schema、修改了公共数据结构或枚举 | `docs/api/*.md`, `docs/contracts/*.md` | 更新字段名、数据类型、必填项与序列化规范 |
| **技术决策记录 (ADR)**| 是否做出了重大技术选型、引入新框架、重大模式重构 | `docs/adr/*.md`, `docs/decisions/*.md` | 新增 ADR 文档（记录背景、备选方案、决策理由与后果） |
| **构建与环境配置** | 是否新增或变更了编译器、系统依赖、环境变量、打包脚本 | `docs/setup.md`, `README.md`, `CONTRIBUTING.md` | 更新先决条件、安装命令、构建命令与启动说明 |
| **代码质量与流程** | 是否更新了分支策略、Lint 规范或测试门禁标准 | `docs/project/process/*.md`, `AGENTS.md` | 更新流程细则与操作守则 |

### 1.2 用户与对外文档 (User & Public Facing Docs)
| 文档类别 | 触发检查条件 | 典型检查路径范例 | 核心核验更新内容 |
|---|---|---|---|
| **快速上手指南** | 是否影响了用户的初始安装、配置或首次执行体验 | `docs/getting_started.md`, `README.md` | 验证快速上手命令的准确性与可执行性 |
| **用户操作手册** | 是否新增/变更了用户可见的功能特性、页面路由或交互模式 | `docs/user_guide.md`, `docs/features/*.md` | 更新操作步骤截图、交互流程与错误提示说明 |
| **CLI 命令行参考** | 是否新增/修改了 CLI 子命令、参数标志（Flags）或默认值 | `docs/cli_reference.md` | 更新参数帮助表格与调用示例 |
| **常见问题 (FAQ)** | 本次开发是否排查解决了典型技术陷阱或环境兼容问题 | `docs/faq.md`, `docs/troubleshooting/*.md` | 提炼为“现象 - 根因 - 解决方案”条目沉淀 |

### 1.3 实施计划与任务跟踪 (Planning & Project Tracking)
| 文档类别 | 触发检查条件 | 典型检查路径范例 | 核心核验更新内容 |
|---|---|---|---|
| **实施方案计划** | 目标达成、所有子任务开发完毕 | `docs/project/plans/YYYY-MM-DD-<feature>.md` | 将计划状态更新为 `[已完成]`，记录最终实际完成时间 |
| **代码现状评估报告** | 阶段 0 产生的既有代码评估文档 | `docs/project/evaluation/*.md` | 归档评估报告，关联最终落地解决的对应 commit |

## 2. 文档更新规范与最佳实践 (Sync Standards)

1. **真实性优先**：
   - 更新文档前，必须通过 `git diff --stat` 确认实际修改的文件与接口；
   - 严禁凭记忆臆造文档，文档中的所有示例命令必须可在本地执行成功。
2. **多语言同步一致性**：
   - 若项目维护了多语言文档（如 `docs/zh/` 与 `docs/en/`），代码逻辑变更必须**同步更新所有对应语言版本**，严禁出现单语种脱节。
3. **独立提交原则 (Independent Commit)**：
   - 文档全向更新宜使用独立的 Git Commit 提交，提交信息严格遵循规范：
     `docs: update <文档名> for <变更原因>`。
