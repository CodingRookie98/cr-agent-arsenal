# 异常恢复与 3-Tries 熔断协议 (Failure Recovery & Escalation Protocol)

## 概述 (Overview)

长程任务中最致命的失控模式是**盲目试错死循环 (Infinite Retry Hell)**：对同一报错反复微调，消耗上下文且破坏既有架构。本协议规范 `Execute` / `Verify` 阶段的**分级自愈、安全回退与非阻塞人类升级仲裁机制**。

---

## 1. 3-Tries 熔断与非阻塞升级 (The 3-Tries Rule & Non-Blocking Escalation)

针对任意单一错误、测试失败或构建异常，智能体连续自主尝试修复的上限严格为 **3 次**。

> **场景级子上限优先**：编译/静态检查失败 **2 次**、重构破坏既有测试 **2 次**、循环摆动（来回撤销重做同一逻辑）**1 次判定**——先触及者先触发对应动作，优先于总上限 3 次生效。

### 1.1 正常修复与前置微观调研

```text
第 1 次失败 ➔ 针对断言、堆栈与契约精准修复
第 2 次失败 ➔ 强制暂停盲改！触发【微观定向调研】(Micro Research)
              ├── 1. 提取精准报错堆栈与编译器核心关键词
              ├── 2. 使用 gh search issues / 全代码库检索排查已知缺陷或内部约束
              ├── 3. 使用 find-docs / context7-cli / web_search 核实官方文档与变更
              └── 4. 基于第一手权威证据制定第 3 次修复方案
第 3 次失败 ➔ 立即触发熔断 (STOP → RECORD → RESEARCH → ESCALATE)
```

### 1.2 熔断四步与非阻塞升级

1. **STOP 冻结**：立即停止写入型工具调用，使用 `git stash push -m "3-tries-frozen"`（或等价安全隔离）暂存实验改动，恢复最后一个 Green 基线；**严禁破坏性 `git checkout .` / `git reset`**。
2. **RECORD 落盘**：生成《自动化熔断报告》（§4 模板）并写盘存档，作为阻塞的客观交付凭据。
3. **RESEARCH 汇证**：汇总微观调研、全库检索与第一性原理诊断，给出 2~3 个可执行方案供人类裁决。
4. **ESCALATE 非阻塞升级**：
   - 将受阻工作项在计划中标记为 **`parked`**，将其下游依赖项标记为 **`blocked-by: <task-id>`**；
   - 主调度**继续推进不依赖该受阻点的独立工作项**——单点熔断不等于整条流水线停摆；
   - 待人类工程师下达明确裁决指令后，开启新一轮 3-Tries 修复周期。

> **外层上限**：`Verify` 阶段的 Delta Re-Loop 迭代上限为 **5 次**（独立计数），达到上限仍未 Zero Blockers 时按同上四步升级人类裁决。

## 2. `Execute` 阶段 TDD 异常自愈矩阵 (Unit TDD Failures)

| 失败场景 | 探测信号 | 上限 | 自愈与安全回退策略 | 升级条件 |
|---|---|:---:|---|---|
| **单元测试失败 (Red)** | 测试未全绿（Exit Code != 0） | 3 次 | 对照契约与断言写最简实现；第 2 次后微观调研；3 次未果 `git stash` 隔离回基线 | 连续 3 次未通过 |
| **编译/静态类型失败** | 编译器、类型检查或 Linter 报错 | 2 次 | 核对类型导入、接口字段与签名；必要时恢复至可编译基线 | 2 次未解决，转依赖/环境排查 |
| **重构破坏既有测试** | 🔵 重构阶段测试变红 | 2 次 | 用 `git stash push -m "failed-refactor"` 隔离实验重构，恢复 Green 基线，禁止牺牲稳定性换抽象 | 2 次未恢复则放弃本次重构 |
| **循环摆动 (Flapping)** | 来回撤销并重做相同两套逻辑 | 1 次 | 立即终止摆动，记录底层设计矛盾 | 出现一次即停并升级 |

## 3. `Verify` 阶段集成与构建异常矩阵 (Integration Failures)

| 异常现象 | 诊断方向 | 恢复策略 | 升级条件 |
|---|---|---|---|
| **单个集成用例失败** | 接口入参/出参微调导致局部契约不匹配 | 定位交互模块，回到 `Execute` 补单测并精准修复 | 尝试超过 3 次 |
| **多模块大面积失败 (>3 用例)** | 底层模型、全局配置或迁移破坏上下游契约 | 立即隔离并回退至集成前状态，回到 `Plan` 重估接口设计 | 失败用例 >5 个立即熔断 |
| **环境/工具链依赖失效** | 缺失系统依赖、动态库、本地服务或代理污染 | **严禁改业务代码**，仅排查环境配置与依赖安装 | 宿主不可自愈环境缺失 |
| **死锁 / 运行超时** | 并发锁竞争或测试进入无限轮询 | 超过基线耗时 2 倍即终止进程，排查锁顺序与异步退出 | 单次超时超 10 分钟 |

## 4. 自动化熔断报告模板 (Escalation Template)

触发熔断时，停止写入型操作并落盘以下结构化报告：

```markdown
## ⚠️ goal-loop 自动化熔断报告 (3-Tries Escalation)

- **受阻任务**: [Task ID 与名称]
- **受阻文件**: `[主文件路径与测试文件路径]`
- **触发阶段**: [`Execute` TDD | `Verify` 集成构建 | `Verify` 终审]
- **已尝试次数**: 3 次（或已触及的场景子上限）
- **核心报错信息**:
    [精准、未经截断的核心报错堆栈，可缩进粘贴或附 .goal-loop/scratchpad.md 指针]
- **已尝试排查路径与失败机理**:
  1. **尝试 1**: [改动简述] → 结果: [报错与机理]
  2. **尝试 2**: [改动简述] → 结果: [报错与机理]
  3. **尝试 3（微观调研后）**: [改动简述] → 结果: [瓶颈所在]
- **微观调研证据链**:
  - **GitHub / 全库检索**: [关联 Issue、内部约束或参考实现]
  - **官方文档 / 规范**: [API 真实行为与已知 Workaround]
- **第一性原理诊断**: [分析无法收敛的根因：需求冲突 / 上游缺陷 / 环境限制]
- **建议方案选项 (2~3 个)**:
  - **选项 1 (推荐)**: [方案描述、改动面与预期效果]
  - **选项 2**: [备选方案与权衡]
- **当前状态与请求裁决**: 本任务已置 `parked`（下游依赖已标 `blocked-by`），其余独立项继续推进；请人类工程师裁决下一步指令。
```
