## 5. 架构规范与行为约束
- **错误处理**: 遇到非法入参或异常状态时，显式抛出/返回项目约定的领域异常，严禁静默吞错；
- **边界防御**: 关键计算与状态流转须做非空与有效性校验，杜绝未定义行为；
- **执行自治**: 遇到局部小歧义若可逆且不越界，按最小影响原则落地并在第 8 节 `risks` 显式汇报；触及公共契约变更或不可逆风险时立即返回 `status: blocked`。

## 7. 严禁事项与安全红线 (Strict Guardrails)
1. **严禁越权编写计划或总结文档**：后台唯一职责是编写白名单内的代码与测试；计划复选框与头部 `Active Checkpoint` 统一由主调度按第 8 节输出契约验真后更新；
2. **严禁套娃派发审查员**：执行子智能体**严禁私自再派发代码审查子智能体**，独立审查权统一由主调度在 `Verify` 阶段行使；
3. **严禁越界改文件与弱化断言**：严禁修改白名单外文件、严禁改动公共核心契约、严禁删减既有测试或降低断言门槛；
4. **严禁运行时向人类提问及破坏性 Git 命令**：所有决策必须自包含于本规约；严禁 `git reset` / `git checkout .` / `git rebase` 等破坏性命令。

---

## 8. 输出契约 (Required Handoff to Orchestrator)

执行完成后必须按以下结构回传；缺任一必填项视为未完成，编排者有权退回重做：

```text
status: done | blocked                # blocked 时禁止宣称交付
changed_files:                        # 实际改动文件清单
  - path: <相对路径>
    kind: added | modified | deleted
git_status_porcelain: |               # 原样粘贴 `git status --porcelain`，证明只改动白名单内文件
tests_run:                            # 真实执行过的验证命令与退出码，禁止伪造
  - command: <命令>
    exit_code: 0
acceptance:                           # 与第 6 节验收命令逐条对应
  - criterion: <验收项>
    result: pass | fail
risks: none                           # 遗留风险、局部裁决偏差或未覆盖边界
blockers: none                        # status=blocked 时必填，按 failure-recovery-protocol 熔断报告格式
```

**编排者职责**：收到本契约后，必须独立复核 `git diff` 与重跑验收命令（Zero-Trust 验收），确认无误后再更新计划复选框与 `Active Checkpoint`。
