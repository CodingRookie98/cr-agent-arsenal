# 变更联动登记模板 (Change Registration Template)

> **用途**：按 [change-impact-matrix.md](../references/change-impact-matrix.md) §3 的 Sync SOP，把一次变更的**影响面 → 同步动作 → 门禁证据**登记成可审计记录（通常落在实施计划、PR 描述或检查点中）。`<...>` 为必填槽位。

## 1. 登记骨架

```markdown
### 变更联动登记 · <变更标识> · YYYY-MM-DD

- **变更范围**：<一句话；含受影响模块>
- **影响面扫描**：<`git diff --name-only HEAD~1` 的关键路径输出>
- **矩阵命中**：<命中的矩阵行，如「核心架构、框架与基础设施」>

| 同步类别 | 目标文件 / 平台 | 动作 | 完成 |
| :--- | :--- | :--- | :--- |
| 契约镜像（API / 模型 / 规则 / UI） | <路径｜不适用> | <更新的行/新增的段> | ☐ |
| 架构与决策（Architecture / MADR） | <路径｜不适用> | <更新架构说明 / 新增 ADR> | ☐ |
| 操作指引与索引（How-To / 入口索引） | <路径｜不适用> | <更新步骤或入口导航> | ☐ |
| 变更记录（Changelog / Issue） | <`CHANGELOG.md` / Issue 链接｜不适用> | <追加发布摘要 / 更新 Issue 状态> | ☐ |

- **门禁证据**：`<校验命令（如 lychee / check-doc-links.py --root docs）>` → Exit <0/非0>（原始输出片段：<粘贴>）
- **未同步项与理由**：<无｜逐条列出并说明为何不适用>
```

## 2. 使用纪律

1. **不得只写结论**：门禁证据必须附实际命令、退出码或原始输出片段，缺失即视为未验证。
2. **不适用也要写**：矩阵未命中的行写「不适用」，留空或省略会被读成遗漏。
3. **未同步项必须显式登记**：不写等于宣称已同步，避免宣称范围超出实际取证。
4. 登记完成且文档/断链校验命令返回 Exit 0 后方可提交。
