# Backlog 条目编号与生命周期规范 (Backlog Entry Specification)

> **控制信息**
> - **规范版本**: V1.0.0
> - **适用范围**: `docs/project/backlog.md` 全部条目的编号赋号、分区流转、关闭闭环与跨文档引用
> - **设计动机**: Sync Mode 待办闭环（[change-impact-matrix.md](./change-impact-matrix.md) 步骤 2）与 changelog / commit / RFC 结晶拆片均需要稳定的条目引用键；backlog 是多写入方活文档，靠措辞文本匹配定位条目在改写与近似条目场景下不可靠

---

## 1. 文件分区结构

backlog.md 是多写入方（RFC 结晶拆片、审查建议、日常追加）共用的活文档，固定三区：

```text
# 待办与后续方向 (Backlog)
## 进行中      # 当前正在推进的条目（可为空，允许占位说明文字）
## 计划中      # 已入库未开工的条目（新增条目的默认落点）
## 已关闭      # 已完成条目的沉淀区，最新在最上（倒序）
```

## 2. 条目编号规则 (BK Identifier)

1. **格式**：`BK-{4 位零填充序号}`，如 `BK-0001`、`BK-0042`，上限 `BK-9999`；
2. **位置**：紧跟复选框之后、任何分类标签与描述之前：
   ```markdown
   - [ ] BK-0013 (P4 审查建议) `_resolve_dest` 探测失败 fallback 分支补 `logger.warning`
   - [x] BK-0012 文件操作命令补齐（真网盘沙箱全链路实测通过，2026-09-30）
   ```
3. **赋号**：新条目编号 = 全文件（含已关闭区）当前最大编号 + 1，由追加方读取文件后机械执行；
4. **只增不复用**：编号一经分配即永久绑定条目；条目关闭后编号随条目保留在已关闭区；条目被删除时其编号永久空缺，严禁补位回收；
5. **仅顶层条目编号**：嵌套子项不编号、不独立引用；某子项需要被 changelog / commit 单独引用时，必须先提升为顶层条目并获得独立编号。

## 3. 条目生命周期与关闭闭环

| 阶段 | 动作 |
|:---|:---|
| 入库 | 新条目落入 `## 计划中`，按第 2 节规则赋号 |
| 开工（可选） | 条目（含子项）整体移入 `## 进行中`，编号不变 |
| 关闭 | 条目（含子项）整体移入 `## 已关闭` 顶部，置为 `[x]`，行尾追加（完成说明，`YYYY-MM-DD`） |

**关闭闭环的信息分工（单一事实源原则）**：
* **backlog 只记完成说明与日期**——服务于人读时间线；
* **Commit SHA 只记 `changelog.md`**——服务于机器审计链；
* 严禁在 backlog 重复维护 SHA，防止双写漂移。

## 4. 跨文档引用约定

changelog 条目、commit message、RFC 结晶拆片与审查报告在引用待办时，一律使用 BK 编号（如 `关闭 BK-0013`、`拆解自 RFC-0002，录入 BK-0021~BK-0023`），严禁以条目措辞片段作为引用键。

## 5. 门禁校验

`audit-doc-health.py` 将 backlog 编号合规纳入交付门禁：顶层条目缺编号、编号格式不合规（未紧跟复选框）或编号重复，均直接阻断 PASS。运行方式见 SKILL.md 模式 2。

## 6. 存量迁移指引

既有无编号 backlog 接入本规范时一次性补号：已关闭区自下而上（时间正序）从 `BK-0001` 递增，计划中区自最大已关闭编号继续递增；迁移当次在修订历史中记录版本升级。
