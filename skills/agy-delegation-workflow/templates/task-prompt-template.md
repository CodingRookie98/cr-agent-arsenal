# agy 独立任务提示词通用规范模板 (Self-Contained Task Prompt Template)

前台智能体在委派代码任务给 `agy` 后台执行智能体时，必须编写完全自包含（Self-Contained）的任务提示词文件（存放在项目根目录 `.agy-tasks/<task-name>.md` 中），严禁依赖前台未声明的隐式上下文。

> [!IMPORTANT]
> **规划技能优先联动**：若当前技能库中存在编写计划或拆解任务的技能（如 `writing-plans`），前台智能体在制定实施方案与拆解子任务时，**必须优先激活该技能**，并结合本模板规定的 **7 维通用黄金标准** 规范化组装每个子任务的 Prompt 内容。

---

## 任务 Prompt 7 维通用黄金标准

每个委派给后台执行器的任务，必须完整覆盖以下 7 个正交维度，不绑定任何特定编程语言或框架：

1. **工作目录与精确文件范围 (Scope & Paths)**：
   - 明确声明绝对工作目录。
   - 严格列出允许新增与修改的目标文件清单，未列出的文件严禁擅自修改。
2. **数据契约与接口模型 (Data Contracts & Interfaces)**：
   - 必须提供确切的数据结构、接口定义或领域类型声明（从已有核心模型提取）。
   - 严禁让后台智能体推测或臆造字段名称与类型。
3. **依赖调用与 API 规范 (API & Dependency Boundaries)**：
   - 明确允许引用的公共模块、外部 SDK、工具库及其合法的函数/类/枚举范围。
   - 严禁编造不存在的 API 签名或私自引入异构第三方库。
4. **数据源与测试夹具规范 (Fixtures & Data Sources)**：
   - 明确测试基线数据、默认常量与夹具配置的规范导入路径。
   - 严禁在业务逻辑中自造内联 Fallback 临时数组或伪造虚假数据。
5. **行为规范与架构约束 (Behavioral & Architectural Constraints)**：
   - 明确错误处理机制（如专用领域异常、显式 Result 模式）、日志规范与交互标准。
   - 严格符合项目既有代码设计风格与命名约定。
6. **自动化验收命令 (Automated Verification Commands)**：
   - 提供可在当前环境完整复现的验证脚本或命令（包括静态类型检查、代码规范 Lint、单元/集成测试）。
   - 后台执行器必须在本地执行并确保 Exit Code 0 全绿。
7. **严禁事项与安全红线 (Strict Guardrails)**：
   - 显式声明禁忌行为（例如严禁编写计划/总结文档、严禁破坏性操作、严禁弱化既有测试断言等）。

## 通用任务 Prompt 结构模板 (Markdown Structure)

```markdown
# 任务目标: [简明扼要描述本次任务的目标，如：实现订单结算核心计算模块]

## 1. 工作目录与目标文件范围
- **工作目录**: [项目根目录绝对路径]
- **涉及文件清单**:
  - 新增核心实现: `[模块主文件路径，如：src/orders/calculator.ext]`
  - 新增单测文件: `[单测对应文件路径，如：tests/orders/test_calculator.ext]`
  - 最小必要集成: `[仅挂载或导出的集成入口文件，如：src/orders/index.ext]` (仅做接口接入，严禁改动无关逻辑)

## 2. 数据契约与接口模型 (严格对齐，严禁臆造)
[直接贴出引用的领域模型、数据类型或接口契约代码]
```[语言标识]
// 引用自项目既有核心契约文件: [相对路径]
[贴出确切的数据结构、接口字段与类型声明，保证单一真相源]
```

## 3. 依赖调用与 API 规范
- **允许使用的公共模块**:
  - `[模块路径/包名]`: 仅允许调用 `[指定函数/类/常量/枚举]`。
- **调用约束**:
  - 严格使用项目既有标准工具（如统一日志工具、统一错误类型），严禁自造简易替代方案。
  - 严禁调用未在文档或依赖清单中声明的私有 API。

## 4. 数据源与测试夹具规范
- **测试/基线数据源**:
  - 测试数据必须从 `[项目测试夹具/Mock数据统一路径]` 导入或按规定工厂函数构建。
  - **严禁**在业务逻辑或测试文件内硬编码随意的全局伪数据、未对齐的内联常量字典/数组。

## 5. 架构与行为约束
- **错误处理**:
  - 遇到非法输入或异常状态时，必须显式抛出/返回项目约定的领域异常，严禁静默吞掉异常。
- **边界防御**:
  - 关键计算与状态流转需做非空与有效性校验，杜绝运行时空指针/未定义错误。

## 6. 自动化验收命令 (后台必须运行并通过全部检查)
```bash
# 1. 静态语法与类型检查 (若项目适用)
[项目的类型检查或编译命令，如：type-checker --target ...]

# 2. 代码风格与规范 Lint
[项目的代码检查命令，如：linter [目标文件]]

# 3. 目标单元测试执行
[针对本模块的新增/现有测试执行命令，如：test-runner [测试文件]]
```

## 7. 严禁事项清单 (Strict Guardrails)
1. **严禁越权编写任何计划、设计或总结文档**（如 `IMPLEMENTATION_PLAN.md`、`task.md`、`TODO.md`）！后台的唯一职责是编写目标生产代码与测试代码。
2. **严禁修改清单之外的任何文件**，严禁改动公共核心契约或未分配模块。
3. **严禁为了跑通测试而降低断言门槛**、删除原有测试用例或注释报错代码。
4. **严禁执行任何破坏性 Git 命令**（如 `git reset`、`git checkout .` 等）。
```
