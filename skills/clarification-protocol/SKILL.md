# 澄清规程 (Clarification Protocol)

## 概述 (Overview)

需求澄清的失控只有两种形态：**问得太少**——把未确认假设当结论落地；**问得太多**——用穷尽细节替代收敛，耗尽决策者注意力。本规程将澄清约束为**先自查、对齐术语、按影响筛问、轻台账留痕、三问收敛**的受控过程。

> **SSOT 边界**：全局提示词只保留一行指针以维持每轮在场；澄清与收敛的完整规程以本技能为准，不在全局层复制细则。

---

## 0. 先自查事实，只问人类决策 (Lookup Before Asking)

- 凡通过读代码、查配置、看文档或目录结构即可确认的客观事实，**严禁打扰用户**；提问前先自主取证。
- 提问只面向机器无法代决的问题：业务目标取舍、约束与范围边界、以及不可逆的架构或契约分叉。

## 1. 术语先行 (Terminology First)

- 澄清需求与边界前，先逐一对齐**易产生两种以上理解的核心术语**，直接登记在 RFC / 计划 / Spec 的术语段落中。
- 易歧义术语属全局前置项，**豁免**下文的低影响转默认假设规则；未对齐术语前，不进入范围与边界澄清。
- 范围以「易引发歧义」为界，**禁止扩张为全量词典**。

## 2. 按影响筛问与软预算 (Impact-Gated Asking & Soft Cap)

- 候选问题按「**依赖强度 × 实现影响**」排序：
  - **HIGH**（影响主干行为、架构或公共契约）：进入本轮提问；需要裁决时给出 **2–3 个可行方案**（优缺点对比 + 推荐理由），引导做选择题而非开放式提问。
  - **LOW**（仅影响局部实现细节）：不占用户注意力，直接转为显式**默认假设**并登记。
- **提问软上限**：单次核心澄清（含 §4 出口自核触发的定向补问）累计默认 **≤ 5 个关键问题**。触顶仍未收敛时，先闭合已明确主干，将次要分叉登记为默认假设；若存在无法代决的高风险分叉，则携四项要素升级人类裁决：**现状 / 已验证事实 / 当前瓶颈 / 待裁具体分叉**。

## 3. 极简单表决策台账 (Lightweight Decision Ledger)

已决项、已排除边界与默认假设必须**即时落盘**于当前 RFC / 计划 / Spec 正文（原地更新，不另建平行冗余台账文件），统一使用 1 张 4 列单表：

```markdown
| 编号 | 类型 | 条目 | 依据 / 影响级别 |
| :--- | :--- | :--- | :--- |
| D-01 | 已决项 | 一句话可执行结论 | 用户裁决（第 1 轮）或证据位置 |
| E-01 | 已排除边界 | 明确不做的方案或范围 | 排除依据（含复开前提，若有） |
| A-01 | 默认假设 | 未提问即采用的具体取值 | 低影响，可低成本反转 |
```

- `类型` 仅取 `已决项` / `已排除边界` / `默认假设`。
- **去重纪律**：无新证据或未触发复开前提，禁止换一种说法重开已决项或已排除边界——**重复提问即违规**。
- **提前收敛**：凡因低影响未提问而直接采用的分支，必须登记为 `默认假设`；未登记即视为未收敛。

## 4. 出口三问内联自核 (Convergence Self-Check)

准备闭合澄清并输出确认文档前，内联核对三问（无需单开「无新问题回合」制造交互疲劳）：

1. 核心业务目标与主干流程是否仍有未明确？
2. 关键边界、契约与异常情况是否仍有未确认？
3. 台账条目之间是否存在相互矛盾？

- **三问皆否即收敛**：闭合主干，将剩余次要分支记为显式默认假设并输出需求确认文档 / RFC / 计划，**不以穷尽细节为出口**；不得用空口「没问题了」替代台账自核。
- **任一为是则继续**：下一轮仅围绕该项定向补问（计入 §2 累计 ≤ 5 题软上限），不发散无关细节。

## 何时使用 / 何时不用

- **使用**：目标宏观或含糊；存在多种不可逆路径；多轮问答中出现发散，或无新证据/未触发复开前提下已决项、已排除边界被换说法重开；需要在「问用户」与「记默认假设」之间取舍。
- **不用**：单文件微调、指令明确的直接执行、或查代码/文档即可回答的只读检索——直接干活即可。
