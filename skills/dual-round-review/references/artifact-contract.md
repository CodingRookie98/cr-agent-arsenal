# 产物契约模板 (Artifact Contract Template)

产物审查（`Review Schema: artifact`）的**唯一判据源**。

代码审查有测试、编译器与运行时作真值；产物（规范、方案、决策书、对外报告）没有。契约就是把真值源
制造出来的那一步——**没有契约，审查必然退化为措辞争论**：红队声称"这句话有歧义"，编排者无法判定
该指控是否成立，只能改措辞，新措辞又产生新歧义，永不收敛。本仓库 2026-10-10 曾发生一次 9 行文档
改动被挂 6 轮对抗审查、产出 216KB 报告的事件，根因正是判据缺失。

---

## 1. 契约模板

```markdown
# 产物契约 (Artifact Contract) · <slug>

- **Intent（要达成什么）**: [该产物存在是为了改变什么 / 让谁做出什么决定]
- **Audience（给谁看 / 谁据此行动）**: [具体读者画像，不是「所有人」]
- **Constraints（不可协商项）**: [法规、既有契约、预算、期限、必须兼容的既有规则]
- **Out of Scope（明确不评）**: [本次不评的维度及理由——列得出才拦得住越界]
- **Evidence Bar（什么算证据）**: [外部可核验事实 / 产物内确切位置 / 受众常识 / 可复现实验]
- **Value Calls（预期的价值取舍点）**: [预先声明哪些取舍无客观判据，预期落入 ⚖️ 不可判定]
```

---

## 2. 冻结规程（硬性）

1. **开审前冻结**：由主智能体在派发 R1 之前写定。**无契约不得开审**（硬门禁）。
2. **逐字内联**：契约以字面值内联进 R1 / R2 提示词——子智能体上下文隔离，无法自行读取文件。
3. **冻结后不可改**：审查期间不得修改契约；R1 必须在报告 §1 **逐字复述**契约全文，作为归档证据。
4. **开审前对人类可见**：主智能体须先输出一行通告（「产物契约已冻结如下，如有异议请在开审前驳回」）。
   人类可在开审前否决或修订——这是契约唯一的滥用防线。
5. **反滥用（R2 的否决权）**：若 R2 判定契约把真实风险排除在 Out of Scope 之外，或 Evidence Bar
   高到无法举证，**R2 有权把契约本身列为 P1 缺陷**（判定为「契约过宽 / 过窄」）并终止本轮审查。

> **诚实边界**：契约为**提示词契约**，非沙箱强制。它的效力来自「冻结 + 归档 + R2 否决权」三者，
> 而非任何机械强制——不得在文档或汇报中表述为「已隔离」或「不可绕过」。

---

## 3. 契约层面的反模式

| 错法 | 后果 | 纠正 |
|---|---|---|
| Intent 写成「提升质量」 | 无判据，任何指控都能挂上去 | 改成可观测结果：谁、在什么场景、做出什么不同决定 |
| Audience 写成「所有人」 | 读者视角失效 | 指定 1–2 个具体读者画像 |
| Out of Scope 留空 | 越界指控无拦截依据，审查无限扩张 | 至少列出 1 条 |
| Evidence Bar 写成「显而易见」 | 举证责任消失 | 明确列 1–4 类可接受的证据形式 |
| 契约由被审查者单方写定且不可见 | 自我豁免 | 见 §2.4 开审前通告 + §2.5 R2 否决权 |
| 把争议点写进 Value Calls 以求免责 | 真实缺陷被预先豁免 | R2 逐条核验：能给出客观判据的争点**不得**留在 Value Calls |

## 4. 与代码模式的对应关系

| 代码模式 | 产物模式 |
|---|---|
| 需求规格（Spec） | 产物契约（本文件） |
| `git diff` 变更行范围锁 | Out of Scope + Constraints 范围锁 |
| `文件:行` 反证据 | Grounds 必须指向产物内确切位置 |
| 历史代码越界 → 强制降级 | 契约外指控 → 强制降级 |
| 回归测试 / 编译当裁判 | Evidence Bar + ⚖️ 不可判定出口当裁判 |
